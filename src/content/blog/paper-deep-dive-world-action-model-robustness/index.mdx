## 1. 论文概述

本文依据 [arXiv v5 正文与附录 A–C](https://arxiv.org/html/2603.22078v5)，代码固定为 [`8f07761`](https://github.com/Robot-Robustness/RoboTwin2.0-Plus/tree/8f077616e5c3c1cb29b88db2323212d51243438a)。精读重点是**扰动如何施加、分数如何汇总、比较能支持什么结论**；其中主表总分存在不能忽略的统计口径问题，见 5.2。

**【Paper】** 论文不提出一个新的 policy，而是回答一个很具体的问题：把视频生成 world model 改造成 World Action Model（WAM）之后，是否真的比典型 Vision-Language-Action（VLA）更能应对训练分布之外的视觉、语言和机器人状态？作者在单臂 LIBERO-Plus 与双臂 RoboTwin 2.0-Plus 上，测试公开 checkpoint，并引用部分已有论文成绩，把扰动拆成可配置维度；并非所有表格条目都由作者在同一实现下重测。

### 一句话总结

**【Analysis】** WAM 的优势更像是“预训练时已经学过视频中的运动规律”，而不是“推理时多算几步就必然更强”：它们在噪声、光照、干扰物布局上经常领先，但在相机视角和初始关节状态改变时并不稳；$π_{0.5}$ 依靠更丰富的机器人与网页数据也能达到相近甚至更好的结果。

### 核心贡献

**【Paper】**

1. 提出 **RoboTwin 2.0-Plus**：在 50 个双臂任务上沿 7 个维度施加结构化扰动（列出的扰动子项实际为 20 个，计数差异见 4.2），并给出 1 个 clean baseline 加 7 个正交分支的评测协议。
2. 将 WAM、经典 VLA 和混合方法（如 MOTUS、VLA-JEPA）放在 LIBERO-Plus 与 RoboTwin 2.0-Plus 上比较，而不是只报告单一干净测试集。
3. 分析视频 backbone 的时空先验、task-specific 数据多样性、action 生成方式与 inference latency 各自对鲁棒性的影响。
4. 给出可复用的 benchmark 代码与配置，官方仓库同时支持数据采集、扰动开关和策略评估。

**【Paper】** 论文最后的结论是有条件的：WAM 通常对视觉扰动更鲁棒，但不是所有扰动都受益；推理开销则是现实部署的主要障碍。

## 2. 背景与相关工作

**【Paper】** 典型 VLA 以 VLM 为 backbone，学习从当前历史状态 $h_t$ 到动作的条件分布：

$$
\pi(a_t\mid h_t).
$$

VLM 的 next-token 或 action diffusion 训练擅长语义和空间 grounding，却未必显式预测“执行动作后画面会怎样”。当测试环境改变光照、背景、杂物或相机时，策略可能依赖训练集中的外观捷径。

**【Paper】** WAM 则从视频生成模型出发。其视频 backbone 在互联网视频上学习时空变化，机器人微调阶段再让 latent 表示与动作关联。论文讨论的代表包括 Cosmos-Policy、GE-Act、LingBot-VA、Fast-WAM 和 DreamZero；MOTUS、VLA-JEPA 作为部分加入 world modeling 的混合路线单独分析。

**【Analysis】** 这里的对照不是“有 world model / 没有 world model”的二元实验。模型同时改变了 backbone、action representation、训练数据、是否做 embodied pre-training、扩散步数和 action chunk，因此论文更准确的定位是**系统性 robustness study**。它能发现设计的关联，但不能把所有差异归因于单一模块。

## 3. 问题定义

### 3.1 评测对象

**【Paper】** 对每个候选 policy，在同一任务集上执行 clean 与扰动分支，记录 episode success rate。论文主要关心四个问题：

| 问题                | 需要回答的证据                                                       |
| ------------------- | -------------------------------------------------------------------- |
| RQ1：WAM 是否鲁棒？ | 两个 benchmark 的总体与分维度成功率                                  |
| RQ2：优势是否普遍？ | camera、robot、language、light、background、noise、layout 的分项结果 |
| RQ3：为何有差异？   | backbone 先验、训练数据与 action/world coupling 的对照               |
| RQ4：代价是什么？   | 每次动作块推理的 wall-clock，并检查硬件、动作长度和去噪配置          |

### 3.2 扰动与成功率

**【Paper】** RoboTwin 2.0-Plus 覆盖 50 个 Aloha-AgileX 双臂任务。完整评测是每任务 8 个配置：clean，以及 Camera、Robot、Language、Light、Background、Noise、Layout 七个只激活一个维度的分支；每个配置运行 50 episodes。按该协议，每个模型有 $50\times8\times50=20,000$ 次计划内评测，其中 17,500 次属于扰动分支。但论文 Table 3 的 Total 并未在所有模型上使用同一种平均口径，不能直接定义成“七个扰动均值”。

**【Analysis】** Clean 分数提供任务能力的参照，但“只打开一个扰动类别”不等于严格配对的因果实验：同类内部可能同时改变几个子项，环境随机数消耗与专家可行性过滤也可能改变实际场景。要区分能力与鲁棒性，应同时看原始成功率、扰动成功率及二者差值；只看 Total 会掩盖 clean 能力差异。

### 3.3 WAM 与 VLA 的条件分解

**【Paper】** 论文用两种抽象描述差别。VLA 直接估计：

$$
\pi_\theta(a_t\mid h_t).
$$

WAM 可能联合生成未来状态与动作：

$$
p_\phi(h_{t+1},a_t\mid h_t),
$$

或先生成未来视觉状态、再由 inverse-dynamics model（IDM）解码动作：

$$
p_\phi(h_{t+1}\mid h_t)\,g_\psi(a_t\mid h_t,h_{t+1}).
$$

有些方法（如 GigaWorld-Policy）采用相反的 action-first 条件生成方向。

**【Analysis】** 这不是声称两类 policy 在理论上不可互相表达；在有限数据、有限算力和不完美目标下，它们把学习难点放在不同位置：VLA 更依赖 embodied data 学动态，WAM 把一部分动态先验交给视频预训练，再学习 action 与未来状态之间的关系。

## 4. 方法

### 4.1 Overall Architecture

![RoboTwin 2.0-Plus 的七类结构化扰动示例（论文 Figure 1）](https://pic.hana0721.top/blog/paper-deep-dive-world-action-model-robustness/perturbation-strip-crop.8dxlvzs3s9.webp)

**【Paper】** 论文的方法主体是“benchmark + comparative protocol”：环境生成器从 clean episode 出发，只打开一个 YAML perturbation branch，候选 policy 读取被扰动的 observation 和 instruction，随后以 success rate 汇总。代码侧的核心数据流是 `task_config/*.yml → task setup / 扰动 → 专家可行性检查 → policy rollout → success check`；数据采集入口与策略评测入口需要分开。

### 4.2 核心模块

#### 七维扰动 taxonomy

**【Paper】** 七个维度与实际子维度如下：

| 维度                  | 子维度 | 具体变化                                    |
| --------------------- | ------ | ------------------------------------------- |
| Sensor Noise          | N1–N5  | motion / Gaussian / zoom / fog / glass blur |
| Light Conditions      | L1–L4  | diffuse color、方向、specular、shadow       |
| Camera Viewpoints     | C1–C3  | 距离、球面位置、yaw/pitch/roll              |
| Robot Initial States  | 1 项   | 关节噪声与夹爪极端初值                      |
| Background Textures   | B1–B2  | 场景主题、桌面材质                          |
| Objects Layout        | O1–O2  | 干扰物数量、目标物位姿                      |
| Language Instructions | R1–R3  | 对话包裹、常识改写、目标状态描述            |

**【Analysis】** 表 6 列出的数量是 $5+4+3+1+2+2+3=20$ 个扰动子项；论文却称 21 个、默认 20/21 激活。README 将 21 解释为 20 个扰动加 clean，因此关闭 C2 后是 19 个扰动子项。本文按具体开关阅读，不把 clean 计入扰动机制。

**【Code】** 官方仓库在 `task_config/` 中把分支声明为 YAML。`demo_vision_noise.yml` 让 RGB 每帧应用当前 episode 选中的一种噪声，五类在 episode 间循环；`demo_light.yml` 仅打开 lighting ablation；`demo_camera.yml` 默认启用 C1/C3、关闭 C2 以避免仿真不稳定；`demo_language_plus.yml` 组合 R1/R2/R3；`demo_background_plus.yml` 和 `demo_objects_plus.yml` 分别启用增强背景与目标位姿扰动。

#### LIBERO-Plus 与 RoboTwin 2.0-Plus

**【Paper】** 附录 B 将两套 benchmark 概括为：LIBERO-Plus 是 MuJoCo/robosuite 上的单臂 Franka Panda，2 路 $256\times256$ 相机、7-dim delta EEF；RoboTwin 2.0-Plus 是 SAPIEN/ManiSkill3 上的 Aloha-AgileX 双臂，3 路 $320\times240$ 相机、14-dim joint position，控制频率约 25–30 Hz。

**【Analysis】** 两套基准能补充不同场景证据，但动作空间、视角数、控制频率、训练数据和扰动实例分布不同，绝对分数不能跨基准直接排序。表 8 的 LIBERO 22,400 条来自 LIBERO-Plus 的增强轨迹采集口径，并不代表每个候选模型都在这些轨迹上训练；Fast-WAM 的 LIBERO checkpoint 恰恰只使用 clean demonstrations。

#### WAM 家族的设计分叉

**【Paper】**

- **Cosmos-Policy** 把 robot state、future image 和 value estimates 编成 latent frames，在同一个 diffusion 过程中做 policy、world model 和 value prediction。
- **GE-Act** 从 Genie Envisioner 的视频 latent 经轻量 flow-matching action decoder 产生 action trajectory。
- **LingBot-VA** 在交错序列中自回归生成 future visual state 与 action，动作可看作 IDM 输出。
- **Fast-WAM** 联合去噪 state/action，但测试时可以省略显式视觉状态生成；其发布方案无需额外 task-agnostic embodied pre-training，但仍依赖已预训练的视频主干和机器人任务示教；省略推理视频并不意味着视频知识免费获得。

**【Analysis】** 这些不是统一训练的模型，且发布版本也未必等于各自论文架构：本研究表 1 特别注明 LingBot-VA 的公开权重采用统一 Transformer，与其论文的 MoT 描述不同。比较能反映所测 checkpoint 的表现，不能直接证明某一架构组件的独立效果。

### 4.3 关键公式

**【Paper】** 用 $h_t$ 简写当前可用的视觉、语言与历史信息（不包含待预测的 $a_t$），VLA 的直接策略为：

$$
\pi(a_t\mid h_t).
$$

WAM 的 IDM 形式为：

$$
p(h_{t+1},a_t\mid h_t)=p(h_{t+1}\mid h_t)g(a_t\mid h_t,h_{t+1}).
$$

其中 $p(h_{t+1}\mid h_t)$ 是未来视觉状态分布，$g$ 从当前与未来状态解码动作；联合去噪则直接拟合联合分布。**【Analysis】** 概率分解是链式法则，任何联合分布都能写成这种形式；它本身不是新的可识别因果结构。要论证显式未来状态提高鲁棒性，需要在相同主干、数据和预算下改变实际条件依赖，再比较结果。

**【Analysis】** 公式揭示了实验假设：若未来状态预测的时空先验能在噪声、光照和 clutter 下保持稳定，$g$ 就可以从较可靠的状态变化中生成动作；但相机位姿和 robot initial state 改变的是几何对应关系，单纯的视频先验未必足够。

### 4.4 Training

**【Paper】** 表 2 整理的是各模型原论文的训练阶段和代表性数据规模，并非本研究为全部 checkpoint 配置的等量训练预算。经典 VLA（如 $π_0$、OpenVLA-OFT、X-VLA）通常需要 cross-embodiment robot data；$π_{0.5}$ 还加入 high-level planning、VQA、captioning、grounding 和 mobile manipulation 数据。WAM 中 Cosmos-Policy 主要做 task-specific trajectories，LingBot-VA 使用约 16k 小时 cross-embodiment data，Fast-WAM 则只做 task-specific finetuning。

**【Paper】** 为了在 RoboTwin 上比较 $π_{0.5}$，作者从预训练 checkpoint 出发，在完整 27.5k RoboTwin demonstrations 上训练 60k gradient steps：AdamW（$β_1=0.9,β_2=0.95$）、gradient clipping 1.0、cosine learning-rate decay（$2.5\times10^{-5}$ 到 $2.5\times10^{-6}$）、batch size 64，并采用 delta joint actions。

### 4.5 Inference

**【Paper】** 评测时模型都处于 closed-loop rollout：policy 根据当前 observation 和 language instruction 输出 action chunk，环境执行后返回下一 observation。WAM 可能还要扩散生成 future visual state；因此其 runtime 不仅包含 action decoder，还包含 state denoising、VAE 与 autoregressive/KV-cache 等开销。

**【Paper】** 表 5 的每块延迟为：$π_{0.5}$ 63 ms、X-VLA 195 ms、GE-Act 300 ms、Cosmos-Policy 390 ms、MOTUS 1175 ms，LingBot-VA 的 RW/RT 配置分别为 480/5230 ms。**Fast-WAM 的 190 ms 是从其原论文引用、在另一套硬件上测得**，v5 表注明确排除了同设备重测。因此 190/63≈3 只能是跨来源数字之比，不能当作控制硬件后的速度差。

**【Analysis】** LingBot-VA RT/RW 的状态/动作去噪次数分别是 25/50 与 3/5；本文的鲁棒性数字对应 RT 配置，不能一边引用其 74.2、一边引用 RW 的 480 ms 组成未经测试的性能点。Chunk 也不同：表 5 中 π₀.₅ 为 50、Cosmos 为 16、LingBot 为 32。每块延迟不是闭环控制频率；异步执行、实际执行前缀和观测刷新还会改变反应时间。

### 4.6 代码实现对照

**【Code】** 官方仓库 [RoboTwin2.0-Plus](https://github.com/Robot-Robustness/RoboTwin2.0-Plus) 是 benchmark 与数据采集实现，不是论文中所有 VLA/WAM 的统一训练仓库。`script/collect_data.py` 读取 `task_config/<name>.yml`，构造 task class，调用 `setup_demo()`、`play_once()` 和 `check_success()`；成功 episode 才保存 trajectory。

**【Code】** 关键实现位置包括：

| 代码位置                             | 实际职责                                                       |
| ------------------------------------ | -------------------------------------------------------------- |
| `task_config/demo_*.yml`             | 选择 clean 或单一扰动分支、episode 数和相机/数据字段           |
| `envs/_base_task.py`                 | 解析 sensor noise、camera、background、object、language 等开关 |
| `envs/camera/camera.py`              | 创建 head / wrist cameras 与相机配置                           |
| `script/collect_data.py`             | 采集 episode、写 seed、保存成功 trajectory                     |
| `script/eval_policy.py`              | 专家筛选可行场景，调用候选策略并记录成功；与采集脚本职责不同   |
| `description/task_instruction_plus/` | 提供 50 tasks × 50 variants 的语言 JSON                        |

**【Code】** 例如 `demo_objects_plus.yml` 将 distractor 数量设为 3–15，并以 2 cm 的 x/y Gaussian noise 与 $±15^\circ$ yaw 扰动目标位姿；`demo_vision_noise.yml` 让五种噪声在 episode 间循环。代码支持逐子维度开关，但论文主协议只汇报七个类别。

**【Code】** 还需核对三个会直接改变复现实验的细节：

- `eval_policy.py` 从策略配置读取 `test_num`，默认 **100**，不是环境 YAML 的 `episode_num: 50`；复现附录每任务 50 次时需显式传入 50。
- 附录说 noise severity 在 2–3 中采样，但 `_base_task.py` 用 `np.random.randint(2, 3)`，上界不含，因此实际固定为 2；五类噪声仍按 episode 编号循环。
- 初始夹爪极值设置后，初始化又无条件调用 `together_open_gripper()`。静态代码显示开爪命令会随后覆盖极值目标，不能仅看 YAML 就断言策略第一帧保留了极端夹爪姿态；要靠仿真状态日志验证。

**【Code】** 评测默认先运行专家规划，跳过规划失败、任务失败或不稳定的种子，再在接受的场景运行策略。这测量的是“专家可行场景上的策略成功率”，不是所有随机扰动场景的无条件成功率。分支可能接受不同种子；NumPy/Torch seed 被设置，但 Python `random.seed` 被注释，描述生成路径仍调用 `random.choice`。因此本文不把相同起始 seed 等同于所有初始状态和语言严格配对。[评测入口与环境实现](https://github.com/Robot-Robustness/RoboTwin2.0-Plus/tree/8f077616e5c3c1cb29b88db2323212d51243438a)

## 5. 实验

### 5.1 Experimental Setup

### 5.3 Ablation Study

**【Paper】** 最有信息量的“自然消融”来自同一 Fast-WAM 架构的两个 checkpoint：RoboTwin checkpoint 在 clean + domain-randomized 27.5k demonstrations 上训练，LIBERO checkpoint 只用 clean demonstrations。前者从原始 91.2% 降到七类扰动均值约 72.7%；后者原始 97.6%、论文报告 Total 51.5%（汇总冲突见上），camera 16.4%、background 53.7%、noise 37.7%。

**【Analysis】** 由于 backbone 与 architecture 相同，这个对照提示 task-specific data diversity 可能重要；但它仍不是严格的随机种子消融，两个 checkpoint 还跨 benchmark、embodiment 和数据生成器，也存在总分口径问题，不能把两者差值全部归因于“是否 domain randomization”，更不能证明它在所有架构中都是必要条件。

**【Paper】** 论文也通过模型家族做结构性对照：MOTUS 使用 video backbone 但由额外 VLM 生成动作，在 RoboTwin 的 robot initial state 维度达到 85.0%；VLA-JEPA 用 human video 的 future-state objective 增强 VLA，在 LIBERO 达到 77.9%。这些中间结果说明，时空先验“如何接入”与“是否存在”同样重要。

### 5.4 Generalization

![Cosmos-Policy 在噪声、光照和背景变化下预测未来图像的示例（论文 Figure 3）](https://pic.hana0721.top/blog/paper-deep-dive-world-action-model-robustness/cosmos-pred-crop.13miky0j6h.webp)

**【Paper】** WAM 的优势主要集中在视觉外观扰动。Cosmos-Policy 在 LIBERO 的 noise、light 和 layout 取得 92.7%、96.5% 和 82.2%；未来图像在噪声输入下仍能恢复运动中的机械臂。相反，异常高饱和背景可能造成空间扭曲和颜色不一致。

**【Paper】** 多数被测 WAM 在 camera 或 robot initial state 维度明显退化。**【Analysis】** 一种合理解释是视角变化影响视觉到动作坐标的对应，初始关节变化影响状态分布与可达路径；但“几何原因”尚未由隔离实验验证。例如 X-VLA 在 Robot 很稳、Camera 很弱，两个维度不能合并成一种模型能力。

**【Analysis】** 这些测量点不呈现简单的“耗时越长越鲁棒”排序：$π_{0.5}$ 63 ms/chunk 却在 LIBERO 取得 85.7%；LingBot-VA 在 RoboTwin 配置为 5230 ms/chunk 才取得 74.2%。Fast-WAM 的引用延迟为 190 ms，但其硬件不同；本文不能由这些跨模型点推出推理算力与鲁棒性之间的因果关系。

## 6. 方法分析

### 6.1 为什么有效？

**【Analysis】** 可以提出三个机制假说；本文的观察性跨模型比较尚不足以验证完整因果链：

1. **时空先验**：视频 backbone 见过大量物体运动、手部运动和镜头变化，这可能帮助保留 blur、light 扰动下的动态线索，但视频数据、容量与训练目标共同变化。
2. **动态—动作耦合**：IDM-style WAM 先问“未来状态应该是什么”，再解释“动作怎样造成它”，提供了一个结构化中间变量；它也可能带来未来预测误差，是否净受益需同模型消融。
3. **数据多样性**：Fast-WAM 的跨 benchmark 对照与“先验不是万能的”相容；若 task-specific demonstrations 只有 clean 场景，video prior 仍可能在未见背景和 camera 上失败。

### 6.2 核心创新

**【Analysis】** 这篇工作的真正创新在于把 robustness 从“某个模型在 clean benchmark 的一个数字”变成可诊断的 profile：扰动 taxonomy、正交配置、两个 embodiment、模型训练数据表和 runtime 表被放在同一个分析框架里。RoboTwin 2.0-Plus 的代码还把 benchmark 变成可扩展的 declarative test suite，而不是一次性脚本。

### 6.3 与已有方法的本质区别

| 维度       | 经典 VLA                                     | WAM / hybrid                                                     |
| ---------- | -------------------------------------------- | ---------------------------------------------------------------- |
| Backbone   | VLM，常以 next-token/action objective 预训练 | 视频生成 world model 或附加 video objective                      |
| 核心条件   | 当前观测直接到 action                        | 联合生成 future state/action，或 IDM 解码                        |
| 鲁棒性来源 | 更丰富的 robot/web/human data                | web-scale video 的 spatiotemporal prior + embodied/task finetune |
| 推理代价   | 通常较低                                     | diffusion denoising、VAE、AR/KV cache 额外开销                   |
| 失败模式   | 对外观/遮挡分布敏感                          | 对几何、语言推理和异常背景仍可能敏感                             |

**【Analysis】** 所以工程选择不是“WAM 取代 VLA”，而是权衡：如果部署预算容许 diffusion、且目标是视觉扰动下的泛化，WAM 值得考虑；如果需要高频控制、已有大量多样机器人数据或 action latency 更重要，$π_{0.5}$ 一类 VLA 可能更合适。

### 6.4 关键假设

**【Analysis】** 解释实验时需要检查三个前提：成功率能否代表目标部署需求；各分支是否有一致的样本、难度和汇总口径；公开权重的数据与动作接口差异是否被充分记录。仅说明差异不等于消除差异，单类别开关也不自动隔离失败原因。

**【Analysis】** 这些假设对 benchmark 很实用，但要谨慎外推到真实机器人：连续轨迹质量、接触力、安全性、恢复行为和长尾组合扰动都没有被 success rate 完整刻画。

## 7. 局限性

### 7.1 研究中明确交代的边界

**【Paper】** 本研究的定量评测集中于两套仿真基准，部分候选模型因权重适配与资源限制未进入主表；模型的 embodied/task-specific 训练数据也不同。结果不能外推为全体 WAM 对全体 VLA、或真机长期部署的统一结论。

### 7.2 自己分析得到的局限

**【Analysis】** 第一，动作表示与执行策略是潜在混杂因素，附录 C 的 chunk 字段还与延迟表不一致：LingBot 为 4 对 32、GE-Act 为 54 对 36、MOTUS 为 48 对 16、X-VLA 为 32 对 30。它们可能涉及不同生成/执行粒度，但论文未逐项解释，不能自行把附录 chunk 当作实测延迟的分母。

**【Analysis】** 第二，主表内部存在汇总口径冲突，且两套基准总分也不是同一分布上的配对测量。第三，camera C2 默认关闭，完整的 3D viewpoint shift 尚未成为主结果。第四，语言 R1/R2/R3 的组合分支把不同难度混在一起，若要研究 language reasoning，应该使用仓库提供的 `demo_language_r2.yml` / `demo_language_r3.yml` 做细分。

## 8. 启发与研究思考

**【Analysis】** 这篇论文最值得带走的不是某个冠军数字，而是三条研究路线：

1. **把 robustness 当作训练目标的分解，而不是最后的测试标签。** noise、light、layout 与 camera、robot state 应分别建模，模型可能在前者变强、后者变弱。
2. **将视频先验与 calibration 先验结合。** WAM 擅长外观与动态，但几何变化需要 camera-to-action、proprioception 和 embodiment-specific adaptation；两者结合可能比继续增大视频 backbone 更划算。
3. **同时优化鲁棒性与 latency。** Fast-WAM 的“训练时预测、测试时省略视觉生成”说明 world-model supervision 不必等于每一步都生成完整视频；蒸馏、少步 denoising、action-only heads 和 asynchronous execution 是自然方向。
4. **扩展 benchmark 的因果诊断。** 除 success rate 外加入 recovery、collision、trajectory smoothness、contact stability，并测试组合扰动和真实 camera/robot calibration shift，才能判断时空先验是否真的提升了可部署性。
