## 1. 论文概述

**论文名称**：《MolmoAct: Action Reasoning Models that can Reason in Space》

**作者**：Jason Lee 等（Allen Institute for AI、University of Washington）

**论文链接**：[arXiv](https://arxiv.org/abs/2508.07917) · **代码**：[allenai/MolmoAct](https://github.com/allenai/MolmoAct) · **项目介绍**：[Ai2 Blog](https://allenai.org/blog/molmoact)

![MolmoAct 的三阶段空间推理总览（论文 Figure 1）](https://pic.hana0721.top/blog/paper-deep-dive-molmoact/fig1_overview.3rbytvxjmt.webp)

### 一句话总结

**【Paper】** MolmoAct 把 VLA 的隐式“看图就出动作”改成显式的三段式推理：从 RGB 估计离散深度、画出末端执行器的 Visual Reasoning Trace，再生成低层 Action Tokens；因此策略不仅能控制机器人，也能被人检查和用轨迹草图 steer。

### 核心贡献

**【Paper】**

1. 提出 Action Reasoning Model（ARM）范式，把 perception、spatial planning 和 control 串成可监督的 token 序列。
2. 用 Depth Perception Tokens 蒸馏 Depth Anything V2 的深度估计，用 2D trace 保存比语言更精确的空间计划。
3. 用 Qwen 词表尾部的 byte-level BPE 符号表示 256 个动作 bin，并公开训练配方；7B-D 的详细训练表报告预训练 9,728 H100 GPU hours，正文另有 9,216 的不一致数字。
4. 发布超过 10,000 条高质量轨迹的 MolmoAct Dataset，以及模型权重、训练代码和数据配方。

## 2. 背景与相关工作

**【Paper】** 传统 VLA 通常直接学习 $p(a\mid I,T)$。这种端到端映射缺少显式深度和中间计划：同一条动作失败时，很难判断是目标理解错、空间定位错，还是控制错；语言 CoT 又会丢失尺度、坐标和时间信息。MolmoAct 的出发点是让中间变量本身就位于机器人真正需要的空间表示中。

**【Analysis】** 这不是把语言 CoT 换成另一种“解释文本”，而是把解释绑定到可渲染的深度 token 和可编辑轨迹上。这样中间结果同时承担监督信号、控制条件和人机交互接口三种角色。

## 3. 问题定义

**【Paper】** 给定多视角 RGB 观测 $I$ 和语言指令 $T$，模型要生成深度字符串 $\mathbf d$、二维末端轨迹 $\boldsymbol\tau$ 以及 $D$ 维离散动作 $\mathbf a$：

$$
(I,T)\longrightarrow(\mathbf d,\boldsymbol\tau,\mathbf a).
$$

- **Observation**：side/front/wrist 等多视角 RGB；部分任务还会把用户画的轨迹叠加到图像。
- **Action**：连续位姿维度按数据集分位数归一化，再量化；夹爪维度单独处理。预训练和 mid-training 预测单步动作，post-training 才引入通常为 $K=8$ 的 chunk。
- **Embodiment**：Google Robot、WidowX、Franka 单臂与双臂，以及 LIBERO 仿真中的 Franka Panda。
- **数据**：OXE 子集（RT-1、BridgeData V2、BC-Z）、多模态 web data、辅助 depth/trace data 与 MolmoAct Dataset。

## 4. 方法

### 4.1 Overall Architecture

![MolmoAct 训练、推理与数据流架构（论文 Figure 2）](https://pic.hana0721.top/blog/paper-deep-dive-molmoact/fig2_model_and_training.8okfnqbbtx.webp)

**【Paper】** backbone 沿用 Molmo 的 ViT、attention pooling + MLP connector 和 decoder-only LLM 设计；主实验使用 7B-D（SigLIP2 + Qwen2.5-7B），7B-O 则使用 CLIP + OLMo2-7B。在语言模型输出空间中依次生成 depth tokens、visual trace tokens 和 action tokens。训练阶段还混合 dense caption、pointing、trajectory drawing 等任务，推理阶段在一次完整的自回归生成过程中依次输出三种结果。“一次生成”仍包含逐 token 的多次前向，不能等同于单次 forward。

### 4.2 核心模块

#### Depth Perception Tokens

**【Paper】** 深度图先由 Depth Anything V2 specialist 估计，再由 VQVAE 压缩成 $M=100$ 个 code index，每个 index 从 128 项 codebook 中选一个，并一一映射成一个 `<DEPTH_k>` token。100 是空间位置数，128 是每个位置可选的离散类别数，二者不能混淆。VLA 只看原始 RGB，却被监督去重建 specialist 的深度字符串，属于 specialist-to-generalist distillation。

**【Code】** `preprocess/processors.py` 中先调用 `DepthAnythingV2.infer_image`，对每张深度图独立做 min-max 归一化并转为 8-bit 灰度，再由 `DepthTokens` 在 $320\times320$ 输入、32 倍下采样下产生 $10\times10=100$ 个 code。输出的是相对深度结构，不能直接当作具有米制尺度、跨帧可比较的 3D 地图；128 个 code 也不是 128 个距离刻度。训练需要教师，机器人在线推理由 MolmoAct 自己预测这些 token。

#### Visual Reasoning Trace

**【Paper】** 轨迹是最多 5 个点的折线 $\boldsymbol\tau=(p_1,\ldots,p_L)$，坐标归一化到 $[0,255]$。$p_1$ 是当前夹爪位置，其余点从未来 episode 均匀采样。标签覆盖当前帧到 episode 终点，而非仅当前 8 步动作窗口。它保留粗略路径顺序，却没有连续时间戳、末端姿态、夹爪开合或接触力；同一条二维折线可能对应多条不同的三维运动。

**【Paper / Code】** 轨迹监督来自另一个 Molmo 的逐帧 pointing：询问夹爪位置，双臂分别询问左右夹爪，再把当前点、终点及至多三个中间点串起；它不是相机标定后投影的无误差机器人真值。`processors.py` 的 `Trace` 过滤检测失败点后均匀采样；`modeling_molmoact.py` 的 `parse_trace` 提取普通数值嵌套列表 `[[u,v],...]`，没有 `<TRAJ_START>` 标签。主视角生成 depth/trace，腕部视角作为附加输入，不是每个视角都生成一套推理链。

#### Action Tokenizer 与 Policy

**【Paper】** 每个动作维度按 1% 到 99% 分位数裁剪后量化为 256 bins，并映射到 Qwen tokenizer 末端的 byte-level BPE symbols。作者认为相邻 bin 所用符号共享部分字符，有利于初始化学习。但字符相似并不构成 embedding 距离单调的数学约束，论文也未报告只替换 token 映射、保持数据和训练预算不变的消融。§2.2 将 9,216 GPU hours 与 GR00T N1.5 的 50,000 比较，而 §4.1 / Table 4 给 7B-D 9,728、7B-O 8,192；数据规模、基础模型和硬件配置也不同，因此不能把总训练成本差异因果归结为这一初始化。

**【Code】** `preprocess/processors.py` 的 `ActionProcessor` 完成 quantile normalization、tokenization 与 chunking；README 在数据预处理入口 `preprocess/action_reasoning_data.py` 中显式传入 `--action-chunk-size 8`；该参数不是 `train_multitask_model.py` 的训练参数。动作反量化还必须选择匹配机器人数据的 `unnorm_key`。

### 4.3 关键公式

三阶段联合概率分解为：

$$
p(\mathbf d,\boldsymbol\tau,\mathbf a\mid I,T)=
\prod_i p(d_i\mid I,T,\mathbf d_{<i})
\prod_j p(\tau_j\mid I,T,\mathbf d,\boldsymbol\tau_{<j})
\prod_k p(a_k\mid I,T,\mathbf d,\boldsymbol\tau,\mathbf a_{<k}).
$$

其中 $d_i$ 是深度 code，$\tau_j$ 是轨迹坐标 token，$a_k$ 是动作维度或 chunk 中的动作 token。**【Analysis】** 这个因子化把误差传播方向固定为“感知 → 计划 → 控制”：深度和轨迹是后续动作可以读取的先行 token。训练时使用示教链的正确前缀，推理时读取自己的预测，故上游错误可能向后传播；同时动作仍直接看得到原始图像和指令，这并不是强制所有控制信息只能经过 depth/trace 的硬瓶颈。可视化有助诊断，却不能单凭输出顺序证明这就是模型决策的忠实解释。

深度字符串写作：

$$
\mathbf d=(\langle\mathrm{DEPTH\_START}\rangle,\langle\mathrm{DEPTH}_{z_1}\rangle,\ldots,\langle\mathrm{DEPTH}_{z_{100}}\rangle,\langle\mathrm{DEPTH\_END}\rangle),
$$

其中 $z_i\in\{1,\ldots,128\}$ 是论文编号；公开 VQVAE 返回的 index 从 0 起，实际字符串使用 `<DEPTH_0>` 到 `<DEPTH_127>`，复现应服从 checkpoint 的 tokenizer 映射。轨迹点 $p_i=(u_i,v_i)$，且 $u_i,v_i\in[0,255]$。

### 4.4 Training

**【Paper】** 预训练抽样权重为 action reasoning 40%、trajectory-conditioned action 40%、独立 depth 7.5%、独立 trace 7.5%、web 5%，不能把 Figure 3 的“原始数据占比”当作优化器实际看到的比例。正文称总计 26.3M 样本，但逐项给出的 10.5M + 10.5M + 1.5M + 1.5M + 2M 相加为 26.0M，Figure 3 左图与图注比例也不一致；可靠可执行的口径是正文抽样权重，公开训练配置合计机器人 80%、辅助 15%、web 5% 与之相符。这些主要是同一机器人帧转换出的不同监督样本，不是独立轨迹数。

**【Paper】** Mid-training 使用约 1M action reasoning + 1M trajectory-conditioned 样本，两个外部视角分别与腕部视角配对，训练 50k steps、128 张 H100。§4.2 写 batch size 128，Table 4 却写 256；此处保留分歧，不将二者拼成唯一确定配方。Post-training 通常每任务 30–50 条示教，LoRA rank 32 / alpha 16；LIBERO 每套件单独训练约 40k–80k steps，Table 7 给出 97M 可训练 adapter 参数，说明“少示教”不等于无需较多适配计算。

![预训练数据混合比例（论文 Figure 3）](https://pic.hana0721.top/blog/paper-deep-dive-molmoact/fig3_datamix.pg2snw7xp.webp)

**【Code】** `scripts/train.py` 实现训练入口和 LoRA；`olmo/data/robot_datasets.py` 注册 MolmoAct 数据集；README 给出的 post-training 配置通常是 LoRA rank 32、alpha 16，LIBERO batch size 128、真实机器人 batch size 64。

### 4.5 Inference

**【Paper】** 推理时给定当前图像和指令，模型先生成深度，再生成轨迹，最后生成动作；执行 $K=8$ 个动作后重新进行 action reasoning。另一种专门训练的 trajectory-conditioned 模式把用户轨迹叠加成 $I^+=I\oplus\boldsymbol\tau$，直接预测 $p(\mathbf a\mid I^+,T)$。根据 §2.4 与附录 G，它不继续走完整 depth→trace→action 链；不能把 steering 解释为仅替换推理链中间 token 后仍执行同一三阶段算法。作者也指出，该模式对图像平面内运动有效，但可能产生错误的深度方向位移。

**【Code】** `experiments/libero/run_libero_eval.py` 和 vLLM 版本都先调用 `parse_depth`、`parse_trace`，再 `parse_action`；`olmo/hf_model/molmoact/modeling_molmoact.py` 与 `experiments/libero/molmoact.py` 提供同一套 parser。

## 5. 实验

### 5.3 Ablation Study

![OOD 泛化与 MolmoAct Dataset 中训练的消融（论文 Figure 6）](https://pic.hana0721.top/blog/paper-deep-dive-molmoact/fig6_1_real_eval_outdist.83as1fgw6p.webp)

![MolmoAct Dataset 对真实任务的增益（论文 Figure 6）](https://pic.hana0721.top/blog/paper-deep-dive-molmoact/fig6_2_real_eval_molmoact_dataset.9rk4ym76lx.webp)

**【Paper】** Mid-training 消融比较 Close Lid、Rotate Pot、Pour Tea；正文称每项 10 次，Table 22 实际各列出编号 0–10 的 11 次。按表中 33 次记录计算，有/无 mid-training 的平均进度为 0.7394/0.6848，差 0.0545，能复现约 5.5 个百分点的报告差值；它是这三个适配任务上的增益，不能外推为所有操纵任务的统一增益。

**【Paper】** Steering 在二选一的 clean/dirty bowl 上测试，附录 D.7 定义：朝正确碗运动计 0.5、抓住计 0.85、抬起计 1。Table 23 的视觉 steering 平均为 0.7467，语言 steering 为 0.4133，差 0.3333；真正得满分的分别是 7/15 与 2/15。因此图文中“75% success rate”实为约 0.75 的进度分。训练数据量也有冲突：正文写 100 条，附录列出干净/脏碗各 50 条直达和各 50 条探索路径，合计 200 条。这个结果支持已训练任务中的交互纠偏，不是任意新草图都可执行的保证。

**【Analysis】** 论文没有在同一基础模型、数据与预算下逐项去掉 depth、future trace、web data 或动作 token 初始化的完整消融。已有 mid-training 和 steering 结果不能替代这些对照，也不能单独证明整条空间推理链每个环节的必要性。

### 5.4 Generalization

**【Paper】** 真实 OOD 测试分别改变语言、目标空间位置、干扰物和未见物体；模拟 variant aggregation 则改变光照、纹理和相机视角。零样本模型的 SimplerEnv Variant Aggregation 为 59.3%，低于自身 Visual Matching 70.5%；额外 RT-1 微调后才达到 72.1%（相对 Visual Matching 71.6% 接近）。不能把微调后的鲁棒性归给零样本 checkpoint，且 72.1 的次高对照是 SpatialVLA 65.8%，差 6.3 个百分点，原文拿 RT-2-X 64.3% 计算“第二名 +7.8”忽略了 SpatialVLA。

**【Paper】** 开放指令人评覆盖五个自定义仿真场景、29 条筛选后指令、100 位评委和 1,500 多次偏好投票，比较的是哪段 rollout 更符合指令：MolmoAct 相对 SpatialVLA Elo 高 109、偏好胜率 58%，相对 OpenVLA 为 81%。这不是 81% 物理任务成功率。另一个 30 张网络图片、87 条提示的 trace 人评只评价画出的轨迹，不验证机器人执行或碰撞可行性。

## 6. 方法分析

### 6.1 为什么有效？

**【Analysis】** 第一，深度 token 给 RGB-only backbone 注入了可压缩的 3D 先验；第二，trace 把长时域规划变成少量几何约束，减少语言描述到控制的语义损失；第三，三段 token 都能用现成的 next-token infrastructure 训练，不需要为每个 embodiment 设计新的 diffusion head。mid-training 消融支持增加 household 数据有帮助，但并未将数据质量、额外优化步骤与结构化监督的各自效应分离。

### 6.2 核心创新

**【Analysis】** 真正的创新不是“增加一个深度估计器”，而是把深度、轨迹和动作放进一个可自回归组合的 token interface：同一接口既连接 perception 与 policy，也连接 robot 与 human operator。

### 6.3 与已有方法的本质区别

**【Paper】** CoT-VLA 生成未来视觉子目标，本身就是 visual CoT，不能归为纯语言任务分解；[TraceVLA](https://arxiv.org/abs/2412.10345) 将轨迹可视化为动作预测的提示输入，也不是主要预测 future trace 的辅助输出。MolmoAct 的区分点是显式预测相对深度 token 和未来末端折线，再条件化生成动作，并额外训练 trace-overlay→action 模式以支持用户 steering。**【Analysis】** 因此它更像“可观测的 latent program”，而不是在动作旁边附加一段解释。

### 6.4 关键假设

- **【Analysis】** 每图归一化的相对深度与 100 个 VQVAE code 能保留足够的任务相关结构；这是假设及设计动机，不是已由逐项消融证明的充分条件。
- **【Analysis】** 2D trace 与低层动作之间存在稳定映射；当遮挡严重、相机外参变化很大或需要接触力反馈时，这个假设可能失效。
- **【Analysis】** action token 的序关系初始化能跨 embodiment 迁移，但不同机器人动作维度和范围仍需 post-training 校准。

## 7. 局限性

### 7.1 作者明确提出的局限

**【Paper】** 附录 G 明确列出四类限制：外部视角看不到夹爪时，trace 与策略都会退化；steering 需要多样且精确的轨迹、充分的路径变化示教，并容易出现相机深度方向误差；额外 reasoning token 和通信增加延迟，使推理频率与采集频率失配；100 个 depth token 对细粒度接触几何可能不足。数据采集的 home 15 Hz、tabletop 20 Hz 不能当作模型闭环控制频率。

### 7.2 自己分析得到的局限

**【Analysis】** 深度 specialist、VQVAE 和 trace 标注把训练管线变复杂；深度 token 是固定长度的压缩，可能丢失细小接触几何；trace 仍是相机平面表示，不能单独表达遮挡后的 3D 路径或力控策略。另一个现实问题是，论文展示的成功率主要来自已校准相机和少量示教，换传感器、控制频率或动作空间时仍需重新验证。

![视觉轨迹 steering 的交互示例（论文 Figure 9）](https://pic.hana0721.top/blog/paper-deep-dive-molmoact/fig9_steerability.7w7k5zuriy.webp)

## 8. 启发与研究思考

**【Analysis】** MolmoAct 给 VLA 研究的启发是：中间表示不必是自然语言，关键是它是否同时满足“可监督、可解释、可控制”。后续可以沿三个方向推进：

1. 用不确定性或多候选 trace 表示动作多模态，而不是只生成一条折线。
2. 将 2D trace 与相机标定、点云或触觉 token 融合，弥补纯 RGB 的遮挡和接触盲区。
3. 把 depth/trace 的早停、缓存和 speculative decoding 纳入控制器设计，降低 reasoning token 对闭环频率的影响。
