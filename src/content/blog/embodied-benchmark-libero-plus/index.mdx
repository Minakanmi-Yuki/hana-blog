LIBERO-Plus 在 LIBERO 的操作任务上改变相机、场景、语言指令和机器人起始状态，用来观察 VLA 在这些变化下，还能不能完成任务。

**鲁棒性**指的是：任务目标保持相同，观察条件或执行起点发生变化后，模型仍能完成任务的能力。

对于使用者，主要有两条路线：直接评测已有模型，或者加入增强数据训练模型，再进行评测。环境和动作接口的基础介绍，可以先看 [LIBERO 使用指南](/blog/embodied-benchmark-libero)。

## 1. 认识 LIBERO-Plus

### 1.1 同一个任务，改变执行条件

LIBERO-Plus 延续 LIBERO 的仿真环境和操作任务。机器人仍然根据图像与语言指令，完成抓取、放置和开关抽屉等操作。

变化主要发生在任务的执行条件上：物体可能换了位置，桌面可能换了纹理，相机也可能从另一个方向观察机械臂。

以“把黑碗放到盘子上”为例，任务目标保持相同，可以分别生成相机角度变化、背景变化和物体位置变化的测试实例。

### 1.2 七类扰动

**扰动（perturbation）** 就是基准对某一类条件施加的变化。LIBERO-Plus 提供以下七类：

| 扰动类别   | 改变的内容                             |
| ---------- | -------------------------------------- |
| Camera     | 第三人称相机的位置、朝向和视野         |
| Robot      | 机械臂的初始姿态                       |
| Language   | 保持任务含义，改写指令表达             |
| Light      | 光照颜色、方向、强度和阴影             |
| Background | 场景、桌面和地面的纹理                 |
| Noise      | 图像模糊、噪声等视觉退化               |
| Layout     | 增加干扰物，或改变目标物体的位置和朝向 |

### 1.3 基础任务与测试实例

基准从 Spatial、Object、Goal、Long 四套任务的 **40 个基础任务**出发，生成扰动实例，再经过筛选和平衡，形成 **10,030 个固定测试实例**。

使用时，可以这样区分：

- **基础任务**：机器人要完成什么，例如“把黑碗放到盘子上”。
- **测试实例**：在一组具体的扰动条件下执行这个任务。
- **一次尝试（episode）**：从实例规定的初始状态出发，运行一次完整操作过程。

每个实例同时属于一个任务套件和一个扰动类别。例如，一个实例可以属于 Spatial 套件，并施加 Camera 扰动。[论文中的基准构建](https://arxiv.org/html/2510.13626v3#A3)

## 2. 开始前的准备

### 2.1 准备模型、环境和场景资源

已有 VLA 模型时，需要准备三部分：

| 资源                       | 用途                             |
| -------------------------- | -------------------------------- |
| 模型 checkpoint 与处理配置 | 加载模型，处理图像输入和动作输出 |
| LIBERO-Plus 环境与任务文件 | 加载扰动任务、初始状态和成功条件 |
| 配套场景资源               | 加载新增物体、纹理和场景         |

先按照 VLA 项目的教程安装模型运行环境，再将其中的 LIBERO 替换为官方 LIBERO-Plus 实现。

在运行模型的 Python 环境中，替换已有的 `libero` 安装：

```bash
git clone https://github.com/sylvestf/LIBERO-plus.git
cd LIBERO-plus
pip uninstall libero
pip install -e .
pip install -r extra_requirements.txt
```

系统依赖可以按照 [官方安装说明](https://github.com/sylvestf/LIBERO-plus#️-installation) 准备。

随后从 [官方场景资源](https://huggingface.co/datasets/Sylvest/LIBERO-plus) 下载 `assets.zip`，解压到仓库的 `libero/libero/` 下。完成后，应能找到：

```text
LIBERO-plus/
└── libero/
    └── libero/
        └── assets/
            ├── new_objects/
            ├── scenes/
            └── textures/
```

如果之前运行过 LIBERO，检查 `~/.libero/config.yaml` 中的路径，让任务、初始状态和场景资源指向 Plus 仓库。

### 2.2 先跑通少量实例

加载模型权重，沿用模型训练时的相机输入、图像缩放和动作处理配置，再选择少量测试实例运行。

无桌面的服务器通常使用 EGL 渲染：

```bash
export MUJOCO_GL=egl
```

第一次运行可以依次确认：环境能加载、相机能出图、模型能输出动作、机械臂能执行动作。保存一段回放，观察扰动是否出现在场景中，再扩展到完整测试集。

## 3. 用自己的 VLA 进行评测

### 3.1 沿用模型的输入与动作处理

评测交互与 LIBERO 基本相同：

```text
任务指令＋当前观测 → VLA → 机器人动作 → 环境更新 → 新观测
```

模型读取当前图像和任务指令，输出动作；适配程序处理动作后，环境控制机械臂执行，并检查任务目标是否完成。

外部相机、腕部相机、机器人状态和历史观测的使用方式，沿用所评测模型的配置。图像预处理、动作归一化还原和夹爪开闭含义，也与模型训练设置对齐。

### 3.2 选择测试实例和尝试次数

官方协议将 `num_trials_per_task` 设置为 **1**，每个扰动实例运行一次：

```python
num_trials_per_task = 1
```

四套任务仍使用 `libero_spatial`、`libero_object`、`libero_goal` 和 `libero_10`。评测程序遍历套件实际包含的全部实例；自定义脚本可以通过 `suite.n_tasks` 获取数量。[官方评测说明](https://github.com/sylvestf/LIBERO-plus#-evaluation)

与原始 LIBERO 常用协议相比：

| 项目         | LIBERO 常用协议            | LIBERO-Plus 官方协议 |
| ------------ | -------------------------- | -------------------- |
| 测试组织     | 四套任务，共 40 个基础任务 | 10,030 个扰动实例    |
| 每项尝试次数 | 每个基础任务通常 50 次     | 每个扰动实例 1 次    |
| 尝试总数     | 通常 2,000 次              | 10,030 次            |
| 主要结果分项 | 四个任务套件               | 七类扰动             |

表中的 LIBERO 次数以 [原始 OpenVLA 配套评测](https://github.com/openvla/openvla/blob/main/experiments/robot/libero/run_libero_eval.py) 为例。

可以先选择少量实例检查程序，再运行一个完整套件，最后评测四个套件。

### 3.3 一次评测如何进行

每个实例都有自己的任务指令、场景和初始状态。模型的评测脚本通过 `get_task_init_states(task_id)` 读取配套初态，每个实例运行一次时使用首个初态。[官方单任务示例](https://github.com/sylvestf/LIBERO-plus/blob/main/benchmark_scripts/render_single_task.py)

### 3.4 如何看七类扰动的成功率

成功率的计算方法是：

```text
某类扰动的成功率 = 该类成功实例数 ÷ 该类测试实例数
```

完整评测后，可以报告七类扰动的成功率，再给出总体成功率。下面是官方结果中的两个模型：

<div className='libero-plus-table-scroll' role='region' aria-label='LIBERO-Plus 官方模型成功率' tabIndex={0}>

| 模型        | Camera | Robot | Language | Light | Background | Noise | Layout | Total |
| ----------- | -----: | ----: | -------: | ----: | ---------: | ----: | -----: | ----: |
| OpenVLA-OFT |  56.4% | 31.9% |    79.5% | 88.7% |      93.3% | 75.8% |  74.2% | 69.6% |
| π₀          |  13.8% |  6.0% |    58.8% | 85.0% |      81.4% | 79.0% |  68.9% | 53.6% |

</div>

这张表可以直接显示模型的薄弱环节。以上两个模型在 Background 上成功率较高，在 Camera 和 Robot 上则明显较低。[官方结果表](https://github.com/sylvestf/LIBERO-plus#-libero-plus-benchmark-leaderboard)

四个任务套件仍然保留。想进一步了解差异时，可以将结果展开为“四套任务 × 七类扰动”，观察问题主要出现在空间关系、物体操作、目标理解还是多步任务中。

### 3.5 如何计算总体成功率

按实例汇总时，总体成功率为：

```text
总体成功率 = 全部成功实例数 ÷ 全部测试实例数
```

也可以先计算七类成功率，再取类别等权平均：

```text
类别等权平均 = 七类扰动的成功率之和 ÷ 7
```

七类扰动的实例数量不同，两种方式会得到不同结果。以 OpenVLA-OFT 为例，七列等权平均为 **71.4%**；按论文公布的各类别实例数加权，约为 **69.6%**，与表中的 `Total` 一致。[论文实例分布](https://arxiv.org/html/2510.13626v3#A3.SS2)

汇报结果时，在表格旁注明汇总方式。按实例汇总回答“这批测试中成功了多少”，类别等权平均则让七类扰动在最终分数中占相同权重。

### 3.6 如何与其他模型比较

比较模型时，使用同一版本的测试集，并对齐初始状态、随机种子和动作预算。

结果旁边注明以下信息：

- 使用哪个 checkpoint，即哪一版模型权重。
- 使用外部相机、腕部相机还是双相机。
- 是否输入机器人状态和历史观测。
- 使用哪些数据训练或微调。

这些信息能帮助读者理解分数背后的条件。例如，双相机模型可以通过腕部视角获得操作区域的近距离信息，这会影响它面对外部相机变化时的表现。

### 3.7 进一步分析评测结果

LIBERO-Plus 还提供 **L1–L5 五档难度**。作者使用 OpenVLA-OFT、π₀、π₀-Fast 和 UniVLA 四个参考模型，根据成功模型的数量划分：

| 难度 | 四个参考模型中成功的数量 |
| ---- | -----------------------: |
| L1   |                        4 |
| L2   |                        3 |
| L3   |                        2 |
| L4   |                        1 |
| L5   |                        0 |

它们表示这些参考模型上的经验难度。评测自己的模型后，可以按等级画成功率曲线，再查看对应的失败回放。[难度划分说明](https://arxiv.org/html/2510.13626v3#A3.SS3)

例如，Camera 成功率低时，可以观察机械臂是否找准目标、抓取点是否偏移；Robot 成功率低时，可以观察从新起点接近物体的过程。

Language 分项还可以配合目标替换实验：把指令中的操作对象换成另一个物体，检查机器人是否跟着改变目标。论文通过删除指令和替换目标，发现部分模型在一些任务中较少利用语言。[语言实验](https://arxiv.org/html/2510.13626v3#S4)

需要研究多个变化同时出现的情况时，还可以进一步测试成对组合扰动。相关实验和机制分析见 [LIBERO-Plus 论文精读](/blog/paper-deep-dive-libero-plus)。

## 4. 使用增强数据训练模型

### 4.1 增强数据里有什么

原始 LIBERO 的四套常用任务各有 10 个任务，每个任务提供 50 条人工演示，合计约 **2,000 条轨迹**。

LIBERO-Plus 论文另外收集了 **22,400 条增强轨迹**，过滤后保留超过 **20,000 条成功轨迹**。增强覆盖干扰物、背景、光照、相机、语言和图像噪声六类变化。[数据构建说明](https://arxiv.org/html/2510.13626v3#A4)

数据生成复用了原 LIBERO 示范中的状态和动作：在变化后的环境中执行原轨迹，记录新的观测，保留成功结果，并去掉无动作步骤。

这样，同一个操作过程可以对应更多图像和指令表达，扩大模型训练时接触到的条件范围。

### 4.2 选择数据版本

选择训练框架后，下载它支持的数据格式：

| 数据版本                                                                                | 使用方式                                            |
| --------------------------------------------------------------------------------------- | --------------------------------------------------- |
| [RLDS](https://huggingface.co/datasets/Sylvest/libero_plus_rlds)                        | 对接 OpenVLA 等使用 RLDS 的训练流程                 |
| [LeRobot](https://huggingface.co/datasets/Sylvest/libero_plus_lerobot)                  | 对接支持该数据版本的 LeRobot 训练流程               |
| [按任务套件组织的数据](https://huggingface.co/datasets/Sylvest/libero_plus_data_4suite) | 根据所训练的 Spatial、Object、Goal 或 Long 套件选择 |

训练时，按照模型要求选择相机输入、机器人状态和动作处理方式。保存 checkpoint 时，同时保存对应的图像处理与动作归一化配置，供评测使用。

### 4.3 训练覆盖了哪些变化

训练布局增强主要加入干扰物；目标物体位姿变化和机器人初态扰动仍是测试集中的额外挑战。训练与测试使用不同的背景纹理、相机角度和噪声参数。

作者使用增强数据微调 OpenVLA-OFT 后，相机扰动成功率从混合训练基线 OpenVLA-OFT_m 的 **55.6% 提升到 92.8%**；机器人初态扰动成功率从 **21.7% 提升到 30.3%**。[官方训练结果](https://github.com/sylvestf/LIBERO-plus#-libero-plus-benchmark-leaderboard)

这些分项结果能帮助判断：哪些变化通过增加训练覆盖得到了改善，哪些条件还需要继续研究。

### 4.4 训练后回到测试集评测

训练完成后，按照第 3 部分在同一版本的 LIBERO-Plus 测试集上运行评测，并报告七类扰动与总体成功率。

可以分别展示两种设置：

- **原数据训练后直接评测**：观察模型面对新测试条件时的鲁棒性。
- **加入增强数据后评测**：观察扰动训练带来的改善。

把训练前后的分项成绩和回放放在一起，就能更清楚地看到模型在哪些条件下进步，以及仍然容易在哪些步骤失败。
