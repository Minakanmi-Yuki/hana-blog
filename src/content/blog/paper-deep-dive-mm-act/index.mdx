## 1. 论文概述

**【Paper】** 《MM-ACT: Learn from Multimodal Parallel Generation to Act》提出一个统一的 Vision-Language-Action（VLA）模型：文本任务规划、未来图像预测和动作 chunk 都在同一个离散 token 空间里生成。模型使用 bidirectional attention，把三种任务写成“给定共享上下文，补全一个被 mask 的 block”。文本与图像使用 re-mask parallel decoding，动作则默认一次前向并行生成整个 chunk。

![MM-ACT 与 AR/Hybrid Unified VLA 的范式对比（论文 Figure 1）](/blog/paper-deep-dive-mm-act/motivation.webp)

### 一句话总结

**【Analysis】** MM-ACT 的关键不是简单增加一个 action head，而是把 VLA 重新表述为 block-level masked-token prediction：同一 Transformer、同一套 mask-and-predict 目标，既负责“下一步做什么”，也负责“做完后会看到什么”和“如何用语言描述子任务”。

### 核心贡献

**【Paper】**

1. 使用 language、vision、action 三个 modality-specific tokenizer，把文本、图像、机器人状态和动作拼成共享序列。
2. 提出 Context-Shared Multimodal Learning：三种目标从相同的多视角观察、任务指令和状态上下文出发，共享模型参数与对同一情境的监督。三种输出分别构成条件生成样本，并不是把未来图像和动作放在同一个输出 block 中联合去噪。
3. 为文本/图像采用多步 re-mask decoding，为动作采用 one-step parallel decoding，在动作质量与控制频率之间做取舍。
4. 在 LIBERO、Franka real-world 和 RoboTwin2.0 上验证，报告 LIBERO 96.3% 套件平均成功率、Franka 72.0% 混合任务得分和 RoboTwin 52.38% 成功率；RoboTwin 中联合文本、图像和动作训练比 action-only 提升 9.25 个百分点。

## 2. 背景与相关工作

**【Paper】** 传统 VLA 往往把预训练 VLM 与动作头拼接。它们擅长语义理解，却不一定显式建模物理变化；视觉预测型方法能够预测未来，却常常缺少任务分解与语言规划。统一 VLA 试图同时生成多种模态，但已有方案通常混合 autoregressive（AR）文本、diffusion/re-mask 图像和动作，导致 attention 机制、训练目标和推理流程不一致。

**【Analysis】** 这篇论文抓住的是“目标不一致”与“控制延迟”两个矛盾：AR 适合文本，却要逐 token 前向；diffusion/re-mask 更适合块状图像或动作，却需要多次前向。MM-ACT 选择统一为 mask predictor，再对不同模态使用不同的解码步数。

## 3. 问题定义

**【Paper】** 给定机器人在时刻 $t$ 的多视角图像 $I_t$、语言指令 $l_t$、状态 $s_t$ 以及可选的历史描述，模型需要完成三类条件生成：

- **MMU / text generation**：输出当前任务的子任务规划 $y^{text}$；
- **T2I / image generation**：预测执行动作 chunk 后的未来图像 $y^{img}$；
- **MM2A / action generation**：输出长度固定的动作 chunk $y^{act}$。

共享上下文记为 $u=(I_t,l_t,s_t,\ldots)$，模态 token 为 $m\in\{\texttt{<|mmu|>},\texttt{<|t2i|>},\texttt{<|mm2a|>}\}$。模型学习的是 $p_\theta(y^m\mid m,u)$，三种条件分布共享参数，但输出相互独立成任务：生成动作时不把模型生成的文本或未来图像作为必经输入。Table 8 还分别改变辅助任务是否读取状态，因此“共享上下文”不应理解成每个实验中三种模态的输入 token 完全一致。

**【Code】** 官方训练配置将 `chunk_size` 设为 8；LIBERO 使用 7 维 Franka action，RoboTwin 配置默认 `action_dim: 16`。action codebook 的大小来自 checkpoint 配置，数据集代码的默认值虽写作 1024，但论文与模型准备脚本使用 2048，因此复现实验应以 checkpoint 的 `model.config.action_vocab_size` 为准。

## 4. 方法

### 4.1 Overall Architecture

![MM-ACT 的共享 token 空间与三种输出 block（论文 Figure 2）](/blog/paper-deep-dive-mm-act/method.webp)

**【Paper】** 多视角图像、语言、状态和模态标记先经过各自 tokenizer，形成交错的 shared context；Transformer 对完整序列做 bidirectional attention，再根据 modal token 在尾部补全文本、图像或动作 block。

### 4.2 核心模块

#### Modality-specific tokenizers

- **文本**：沿用 LLaDA tokenizer；文本 block 固定为 256，短答案用 `<eos>` 补齐。
- **图像**：采用 Show-o 的 MAGVIT-v2 quantizer；图像先 pad 成正方形、缩放到 $256\times256$，编码为 256 个 image tokens，生成后再解码回图像。
- **状态与动作**：对归一化到 $[-1,1]$ 的连续标量做 bin quantization。每个标量对应一个 action token，生成后反量化回连续值。

**【Code】** `training/robotwin_dataset.py` 的 `quantize_state` 与 `quantize_action` 实现线性映射：$v\mapsto round((v+1)(B-1)/2)$；部署脚本再使用相反映射恢复动作。

#### Shared context 与 modal token

**【Paper】** 每种任务的上下文都是 `modal token + shared input`。`shared input` 交错包含多视角图像 token、任务指令、描述和可选 robot state。上下文之后追加固定长度的 mask block：图像为 256，动作长度为 $d_{action}\times N_{chunk}$。

**【Analysis】** modal token 指定当前要补全的模态。未来图像标签取自专家执行当前 action chunk 后的帧，但图像分支并未以候选 action chunk 为条件；它学习的是任务条件下专家接下来可能到达的画面，不能直接用作比较任意候选动作的反事实模拟器。

**【Paper】** 附录 A 的规划文本也有明确来源：RoboTwin 记录脚本中抓取、移动、放置 primitive 的调用与完成时间，再填入“总任务—完整计划—已完成部分—接下来子任务”的模板；LIBERO-Long 则人工标注子任务边界。这是结构化阶段监督，而非自由生成并经机器人执行验证的长链推理。

#### Bidirectional Transformer

**【Paper】** MM-ACT 使用带双向 attention 的 mask-token predictor，所有 masked positions 可以在一次 forward 中同时得到 logits。相比 AR VLA，它避免为每个 action scalar 逐 token 运行完整网络；相比混合式模型，它不需要在 AR 与 diffusion head 之间切换。

### 4.3 关键公式

对目标序列 $x_0=(x_0^1,\ldots,x_0^L)$，每个位置独立以 $p_{mask}=f_m(t)$ 被替换为 `<mask>`：

$$
q_t(x_t^i\mid x_0^i)=(1-f_m(t))\mathbf{1}[x_t^i=x_0^i]+f_m(t)\mathbf{1}[x_t^i=\texttt{<mask>}].
$$

**【Paper】** 文本使用 $f_{text}(t)=t$，图像使用 $f_{img}(t)=\cos(\frac{\pi}{2}(1-t))$；动作采用全 mask 的单步配方。动作训练固定 $t=1$，即整个 action block 从全 mask 状态开始，直接学习一次性补全。

统一损失只在被 mask 的位置计算：

$$
\mathcal{L}(\theta)=-\mathbb{E}\left[\sum_{m\in\mathcal{M}}\frac{\lambda_m}{t}\sum_{i\in\mathcal{I}_m}\mathbf{1}[x_t^i=\texttt{<mask>}]\log p_\theta(x_0^i\mid C_m,x_t)\right].
$$

其中 $\mathcal{M}$ 是三种模态，$\lambda_m$ 控制各任务的梯度权重，$C_m$ 是带 modal token 的 shared context。该式的含义是：三种任务可以使用不同数据 block，但优化器看到的是同一类 masked-token cross-entropy。

### 4.4 Training

**【Paper】** 所有模型从 MMaDA 的多模态预训练权重开始，再在目标机器人数据上训练；不是先统一进行大规模机器人动作预训练。两阶段安排只适用于有辅助模态的配置，action-only vanilla 直接训练动作。RoboTwin 的 +Text / +Image 各先单独训练辅助模态 500 steps，再以辅助权重 0.1、动作权重 1 联合训练约 27k steps；+Text&Image 先共同训练文本和图像 500 steps，再将两者权重各降到 0.05。

**【Paper】** LIBERO 每个套件分别训练模型，附录 C 给出的 Object / Spatial / Goal / Long 步数约为 9k / 7.5k / 8.5k / 17.5k；正文的“平均约 11k”不能作为每个套件的精确配置。只有 Long 的 +Text 先进行约 800 steps 文本训练，再以文本 0.05、动作 1 联合训练。Franka 每个任务单独训练约 8k steps；实验 batch size 为 128、chunk size 为 8。

**【Code】** `configs/mmact_robotwin_mix.yaml` 默认 `co_action/co_t2i/co_mmu=True`、`action_weight=1.0`、`t2i_weight=0.05`、`mmu_weight=0.05`，优化器是 AdamW，learning rate 为 $5\times10^{-5}$，warmup 500 steps。`training/train_mmact_robotwin_mix.py` 把 action、T2I、MMU batch 拼接后一次 forward，再按配置权重求和。

### 4.5 Inference

**【Paper】** 部署时只需生成动作。模型把 action block 初始化为 mask，一次 forward 同时得到所有位置的 logits，采样后反量化成连续动作。论文所说最高约 40 Hz 是每秒生成约 5 个、每个包含 8 个动作的 chunk 吞吐量，不是每秒 40 次读取新观测并重新决策；Table 6 的 0.22 s/chunk 对应约 4.5 chunks/s、36.4 actions/s。

**【Code】** 当前 `experiments/robot/libero/run_libero_eval.py` 截取 `action_chunk[:8]` 后依次执行；RoboTwin 的 `deploy_policy.py` 也遍历整个 chunk。原文未规定“只执行第一个动作”，该说法与公开评测循环不符。chunk 内虽有低层控制反馈，但策略不会在每个动作后重新生成剩余序列。

**【Analysis】** 双向 attention 让每个输出位置看到共同上下文与其他 masked positions，却不等于一次采样已条件化于其他位置最终选中的值。单步解码没有把已采样动作 token 再输入模型进行一致性修正；更长序列为何从 re-mask 获益，应从这一区别理解。

**【Code】** `MMACTModelLM.action_generate` 同时支持 one-step 和 re-mask 路径，实际是否一次完成由 `timesteps` 与部署配置控制；RoboTwin `deploy_policy.py` 与通用部署类默认构造 6-step 接口，LIBERO 的公开评测示例则显式传入 1，但论文实验最终选择 one-step action decoding。代码因此比论文叙述更通用，复现论文设置时需要显式把 action generation 的步数设为 1。

## 5. 实验

### 5.1 Experimental Setup

**【Paper】** 实验覆盖三个层次：LIBERO 四个子基准（Spatial、Object、Goal、Long）的 Franka 仿真；RoboTwin2.0 的 Agilex Piper 双臂、八个任务类型的未见指令、场景与物体位置组合；以及 Franka Research 3 真实机器人上的 Press Button、Stack Block、Sort Vegetables and Fruits。这八种 RoboTwin 任务都参与训练，各采集 500 条专家轨迹，过滤后约 70k 个训练样本；这里的 unseen 不是未见任务类型。RoboTwin 使用这些样本联合训练，Franka 每个任务收集 100 条 teleoperation demonstrations。

![Franka Research 3 的真实机器人设置与三个任务（论文 Figure 4）](/blog/paper-deep-dive-mm-act/franka.webp)

### 5.2 Main Results

| Benchmark              |        MM-ACT 结果 | 对比结论                                                                                                                        |
| ---------------------- | -----------------: | ------------------------------------------------------------------------------------------------------------------------------- |
| LIBERO average SR      |          **96.3%** | Spatial 97.8、Object 99.4、Goal 94.8 使用 vanilla；Long 93.0 使用 +Text。四个单独训练模型的平均，不是一个三模态模型的统一成绩。 |
| LIBERO-Long            |     93.0%（+Text） | 相比 action-only vanilla 的 88.0%，任务规划联合训练提升 5.0 个百分点。                                                          |
| RoboTwin2.0（8 tasks） |         **52.38%** | 高于 $\pi_0$ 的 48.13% 与 OpenVLA-OFT 的 23.13%。                                                                               |
| Franka real-world      | **72.0% 混合得分** | 每任务每模型 20 次测试；按键 80%、叠块 70% 是整任务成功率，分拣 66% 是正确归置物体比例。                                        |

**【Analysis】** 这些结果支持离散统一模型能够学到有竞争力的动作策略，但不能把三张表合成一个通用 checkpoint 的能力。Franka 72.0 相对 $\pi_0$ 70.0 高 2 个百分点，叠块两者同为 70%；在每任务 20 次、没有置信区间的条件下，不宜称为显著优势。跨模型预训练数据也不同，机制归因应主要看 MM-ACT 内部消融。

### 5.3 Ablation Study

![Context-Shared Multimodal Learning 的训练数据构造（论文 Figure 3）](/blog/paper-deep-dive-mm-act/training.webp)

**【Paper】** RoboTwin action-only baseline 的平均成功率是 43.13%。加入 text、image、text+image 后分别为 46.50%（+3.37）、48.75%（+5.62）和 52.38%（+9.25）。这支持所测试配方中的辅助监督互补，但没有固定总计算量或打乱上下文对应关系的对照；辅助配置还多出 Stage 1，因而尚未单独证明“相同上下文”本身是收益的必要原因。分任务也并非一致改善，例如 Lift Pot 从 vanilla 的 40% 降至三模态的 31%。

动作解码策略也揭示了效率边界：chunk size 8 时 one-step 为 43.13%、0.22 s，re-mask（6 steps）为 42.38%、1.06 s；chunk size 16 时 one-step 为 43.75%、0.23 s，re-mask 达到 56.75%、1.06 s，提升 13 个百分点。这个 action-only 长 chunk 配置甚至高于三模态默认配置的 52.38%，所以结论是质量与延迟的取舍，不能笼统说跨模态收益一定大于解码收益。论文因此选择 chunk 8 + one-step 作为实时控制默认值。

**【Paper】** Table 7 改变的是辅助模态训练所对应的 one-step / re-mask 配方，部署动作时并不需要先运行它们：image re-mask 达到 48.75%，高于 image one-step 的 46.13%；text one-step 与 re-mask 分别为 46.63% 和 46.50%。状态是否放入上下文也不同：text context 中加入 state 后为 43.50%，image context 中加入 state 后升至 51.50%。

### 5.4 Generalization

![RoboTwin unseen 场景中的未来图像预测（论文 Figure 5）](/blog/paper-deep-dive-mm-act/image-generation.webp)

**【Paper】** Table 4 测试 +Image 配置在 1,000 个未见样本上的预测：Stage 1→2，PSNR 12.08→14.23、SSIM 0.79→0.80、LPIPS 0.11→0.09。Table 5 则测试另一个 +Text 配置，1,000 次文本规划评估由 81.5% 降至 68.7%。后者定义为 GPT-4o 判断生成计划与参考计划意图、决策一致并回答 yes 的比例（Figure 7 给出完整提示），不是人类审定准确率，也不是生成计划的实际执行成功率。

**【Analysis】** 两张表不属于同一个三模态 checkpoint 的同时测量。作者结合文本 loss 很快接近零而图像 loss 缓慢下降，提出文本过拟合解释；但这仍不能排除动作微调造成的干扰或自动评判误差。可以确认的是，动作获益并不保证辅助模态的泛化同步改善。

## 6. 方法分析

### 6.1 为什么有效？

**【Analysis】** 动作、未来图像和子任务文本都由同一份 observation-conditioned context 产生。文本迫使模型编码“下一步子任务”，图像迫使模型编码“动作后的状态变化”，动作则必须把这些语义和动力学线索落到可执行 token。共享 backbone 因此获得了比 action-only 更丰富的训练信号。

### 6.2 核心创新

1. **统一目标**：将 AR token prediction 与 diffusion-like denoising 都改写成 masked-token cross-entropy。
2. **统一上下文**：三种监督关联同一情境，但按模态构造独立样本；状态等可选字段可不同，损失仍是多任务加权和。
3. **按模态分配解码预算**：文本/图像用多步 re-mask，动作使用一次并行预测，把算力优先留给控制频率。
4. **离散 action representation**：连续控制通过 bin tokenizer 进入与文本、图像兼容的词表。

### 6.3 与已有方法的本质区别

| 路线               | 文本       | 图像       | 动作                | 主要代价                                             |
| ------------------ | ---------- | ---------- | ------------------- | ---------------------------------------------------- |
| AR unified VLA     | AR         | AR         | AR                  | 动作逐 token，延迟高。                               |
| Hybrid unified VLA | AR         | PD/re-mask | PD/re-mask          | 需要混合 attention 与训练目标。                      |
| MM-ACT             | block mask | block mask | one-step block mask | 结构简单，但 action 一步预测依赖离散化和固定 chunk。 |

### 6.4 关键假设

- **【Paper】** 任务规划、未来图像和动作可以从同一时刻的 shared context 学到互补关系。
- **【Analysis】** action block 的固定长度足以覆盖控制需要；超过该 horizon 的长期规划由下一次滚动预测承担。
- **【Analysis】** 将连续动作量化为 2048 bins 的离散 token 不会造成决定性控制误差。
- **【Analysis】** 训练数据中的子任务文本与未来图像标注足够可靠，否则跨模态监督可能把噪声传给 action policy。

## 7. 局限性

### 7.1 作者明确提出的局限

**【Paper】** 论文没有单独列出长篇 limitation section，但实验明确显示 Stage 2 会使文本规划泛化从 81.5% 降到 68.7%，说明联合训练存在模态间的负迁移；同时，长 chunk 的 re-mask 虽提高成功率，却带来约五倍推理时间。

### 7.2 自己分析得到的局限

- **【Analysis】** 论文的 one-step action 结果依赖固定 chunk size 8；对于更长动作序列，实验已显示 one-step 可能不如 re-mask。
- **【Analysis】** action token 的 bin quantization 将连续控制误差离散化，论文没有给出 codebook size、控制频率与精度之间的系统敏感性实验。
- **【Analysis】** 真实机器人只覆盖三个任务，且每任务 100 条示教；相比大规模 VLA 预训练，跨 embodiment 和跨任务扩展仍未充分验证。
- **【Code】** 仓库同时保留了 one-step 与多步接口，默认参数和论文实验设置并不完全相同；RoboTwin 默认可能使用 6 步，而 LIBERO 示例明确使用 1 步。另一个复现细节是，当前 `action_generate` 对 softmax 概率调用 `torch.multinomial`；`temperature` 主要参与 re-mask 选择，并不直接把动作 token 采样变成 argmax，不能仅以附录“temperature=0”推断动作解码完全确定。

## 8. 启发与研究思考

**【Analysis】** MM-ACT 提供了一个值得继续追问的设计空间：多模态辅助目标的价值可能不在于部署时生成它们，而在于训练时迫使策略学习更好的 latent state。后续可以沿三个方向推进：

1. 用 uncertainty-aware loss 或 gradient surgery 缓解 Stage 2 对文本的负迁移；
2. 让 action chunk size 与任务阶段、速度或置信度自适应，而不是固定为 8；
3. 把 depth、触觉、接触事件等新模态以同样的 tokenizer + mask block 方式接入，测试“共享上下文”能否扩展到真正的 physical state modeling。
