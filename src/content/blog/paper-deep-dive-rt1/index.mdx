### 一句话总结

**【Paper】** RT-1 把“图像 + 自然语言指令 $\rightarrow$ 机器人动作”视为 sequence modeling：FiLM-EfficientNet 提取语言条件视觉 token，TokenLearner 压缩 token，decoder-only Transformer 预测离散动作。模型约 35M 参数，在 13 台机器人、17 个月、约 130k 条演示上学习 744 条指令，并以 3 Hz 闭环执行。

### 核心贡献

**【Paper】**

1. 提出实时约束下的 Robotics Transformer 架构。
2. 建立约 130k episodes、13 台机器人、744 条指令的数据集。
3. 系统验证 model size、data quantity、data diversity、simulation 和 multi-robot data。
4. 全文各种模型与设置合计超过 3000 次真实试验；Table 2 中 RT-1 的 seen、unseen、distractor、background 成功率分别为 97%、76%、83%、59%。

**【Analysis】** RT-1 的关键不是单纯堆 Transformer，而是语言早期融合、视觉 token 压缩、非自回归动作头与高多样性数据的组合。

## 2. 背景与相关工作

**【Paper】** 机器人 imitation learning 的数据采集昂贵，论文借鉴视觉和 NLP 的大模型范式，问一个 backbone 能否吸收开放式多任务数据并重组已见 skill 与 object。

- **语言条件策略**：通常由 CNN/MLP 做动作回归，容量有限。
- **Transformer policy**：Gato、Behavior Transformer 序列化轨迹，但没有同时解决语言融合与实时延迟。
- **高层规划 + 低层控制**：SayCan 先规划技能，再调用单技能 controller；RT-1 试图把多技能 controller 做成 backbone。

**【Analysis】** RT-1 主要做已见 verb 与 noun 的组合泛化，并不等于开放词汇机器人。

## 3. 问题定义

**【Paper】** 策略接收语言指令和最近 6 帧 $300\times300$ RGB 图像，输出 arm、base、mode 动作，直到 terminate 或达到时间上限。

| 项目        | 定义                                                      |
| ----------- | --------------------------------------------------------- |
| Embodiment  | 7DoF arm、两指夹爪、移动底座                              |
| Arm action  | 位移、旋转和 gripper opening，共 7 维                     |
| Base action | $x,y,yaw$，共 3 维                                        |
| Mode        | arm / base / terminate                                    |
| Action      | 连续维度均匀分为 256 bins                                 |
| Training    | 成功 tele-operation demonstration 上的 behavioral cloning |
| Runtime     | 约 3 Hz，模型预算小于 100 ms                              |

**【Code】** `RT1ActionTokenizer` 将浮点 action 映射到 256 个桶；`int32` 输入采用 one-hot 类别，tokenizer 将其压成一个类别索引。论文的 7 维 arm + 3 维 base + 1 维 mode 共 11 个动作 token；实际代码按 `action_spec` 决定维数，不应把注释中不含底座的 8-token 示例当成论文完整动作空间。

## 4. 方法

### 4.1 Overall Architecture

![RT-1 完整架构：USE、FiLM-EfficientNet、TokenLearner 与 Transformer（论文 Figure 3）](https://pic.hana0721.top/blog/paper-deep-dive-rt1/rt1-full-model-crop.webp)

**【Paper】** 6 帧图像经过 ImageNet-pretrained EfficientNet-B3，USE 指令 embedding 通过 identity-initialized FiLM 注入；81 个视觉 token 经 TokenLearner 压成 8 个，6 帧形成 48 个上下文 token，输入 8 层 decoder-only Transformer。

**【Analysis】** FiLM 让“该看什么”在 CNN 提取视觉特征时就受指令控制；TokenLearner 对空间特征做学习到的软加权组合，生成 8 个 token，并不是挑出 8 个像素或固定裁块。48 是视觉上下文 token 数，公开网络还为每个时间步插入动作占位槽，不能直接等同于 Transformer 的全部输入序列长度。

### 4.2 核心模块

**【Paper】** EfficientNet 输出 $9\times9\times512$ feature map，即 81 个视觉 token；FiLM 使用零初始化的 $\gamma,\beta$，保持预训练网络初始为 identity；TokenLearner 输出每帧 8 个 learned token；Transformer 使用 8 层 self-attention、约 19M 参数。

**【Code】** film_conditioning_layer.py 实现 $(1+\gamma(c))\odot h+\beta(c)$；configs/transformer_mixin.gin 默认 8 layers、8 heads、layer size 128、feed-forward size 512、dropout 0.1、vocab size 256。

对连续维度 $a_j\in[a_j^{\min},a_j^{\max}]$：

$$b_j=\left\lfloor\frac{a_j-a_j^{\min}}{a_j^{\max}-a_j^{\min}}(256-1)\right\rfloor.$$

**【Code】** `tokenize` 先 clip、归一化、向下取整；`detokenize` 对连续量执行反变换。将非法索引回退到 0 的逻辑仅针对离散类别字段，例如 mode；连续动作的 256 个索引都对应其 spec 内的值。量化间隔为 $(a_j^{\max}-a_j^{\min})/255$，所以同样的词表大小并不意味着各动作维度具有相同物理精度。

### 4.3 关键公式

$$
\mathcal L_{\mathrm{BC}}
=-\frac{1}{TK}\sum_{t=1}^{T}\sum_{k=1}^{K}
\log\operatorname{softmax}(z_{t,k})[b_{t,k}].
$$

**【Analysis】** 这是把行为克隆写成逐时间步、逐动作维度分类的概念式，$T=6$，$K$ 由 action spec 决定；不应理解为在生成自然语言。各维分类分布可以有多个峰，但非自回归分解并未显式表示一个动作不同维度之间的条件依赖。

**【Code】** `transformer_network.py` 在整个窗口的动作位置计算 sparse CE，另外除以 `batch_size × T × 每步全部token数`，再由 agent 平均，因此数值归一化并非上式的逐项复刻。`SequenceAgent` 的 `~time_steps.is_last()` 排除的是标为 **episode LAST** 的时间步，不是每个 6 帧窗口的最后一帧；最后一帧的动作输出与全窗口训练损失也应分开理解。

### 4.5 Inference

**【Paper】** RT-1 约以 3 Hz 闭环执行；TokenLearner 和重用重叠窗口 token 分别带来约 2.4 倍和 1.7 倍加速。Table 13 报告网络推理 15 ms，而低于 100 ms 是网络预算；二者都不是完整机器人周期。附录 C.1 从捕获观测起设置 280 ms 固定等待以消除系统延迟抖动，控制频率还受相机和通信影响。

**【Code】** `_generate_masks()` 同时保证时间因果性，并屏蔽动作查询对过去及当前动作 token 的注意力；`_assemble_input_token_sequence()` 更直接把动作 embedding 清零。因此动作值没有作为后续维度的条件输入。公开 `call()` 仍保留逐维循环，反复调用 Transformer 并取 argmax；不能仅凭“非自回归”就宣称这份实现一次前向并行输出全部动作，也不能把其未经实测的延迟直接等同论文 15 ms。缓存的是历史图像 token，而非整条推理链的 KV cache。

## 5. 实验

### 5.1 Experimental Setup

![RT-1 的训练教室、真实厨房和移动机械臂（论文 Figure 2）](https://pic.hana0721.top/blog/paper-deep-dive-rt1/robot-setup-crop.webp)

**【Paper】** 数据来自 13 台 Everyday Robots，收集 17 个月；测试使用 classroom、Kitchen1、Kitchen2，覆盖 seen/unseen instructions、distractor/background robustness 与长时序指令。baseline 与 RT-1 使用同一份大规模数据。这里的 Gato 是用作者数据重训、为实时性缩小至 37M 的架构对照，不是原始 1.2B 通才模型；BC-Z XL 也按相近参数量扩展。比较检验的是这套数据与时延条件下的设计组合，不能据此宣布某类基础模型普遍落后。

### 5.2 Main Results

![RT-1 与 Gato、BC-Z 的成功率（论文 Table 2）](https://pic.hana0721.top/blog/paper-deep-dive-rt1/main-baselines-crop.webp)

| 模型     |   Seen | Unseen | Distractors | Backgrounds |
| -------- | -----: | -----: | ----------: | ----------: |
| Gato     |     65 |     52 |          43 |          35 |
| BC-Z     |     72 |     19 |          47 |          41 |
| BC-Z XL  |     56 |     43 |          23 |          35 |
| **RT-1** | **97** | **76** |      **83** |      **59** |

**【Paper】** Table 2 的 unseen 是已见技能与物体的未见组合，不是全新运动技能。97% 的评测数量在论文内部存在不一致：§6.1–6.2 写 200 余条已见指令、21 条未见指令，附录 D.1 却写 744 条已见、53 条未见，Table 8 也列出 53 条。附录还说明 seen 采用按 skill 加权的汇总。因此这里保留原表百分比，但不能把它确定解释为“744 条指令逐条测试的总体成功率”，也不能从这些计数自行推算置信区间。

**【Paper】** SayCan 实验的两个厨房各有 15 条高层指令，平均 9.6 步、其中平均 2.4 个 manipulation skill；两边 execution success 都为 67%，planning success 都为 87%。规划仍由语言模型与 MT-Opt value function 提供，RT-1 是其中的操作策略。最多 50 步来自补充视频展示，不是这张成功率表的平均任务长度。

**【Analysis】** 更困难的真实场景也不是全面占优：Table 3 中 RT-1 在 L2 与 BC-Z XL 同为 75%，L3 与 BC-Z 同为 50%。背景 59% 和 L3 50% 比 headline 更能提醒我们，组合泛化并未消除环境迁移问题。

### 5.3 Ablation Study

![数据量与数据多样性消融（论文 Table 7）](https://pic.hana0721.top/blog/paper-deep-dive-rt1/data-ablation-crop.webp)

**【Paper】** 完整数据的 seen/unseen/distractor/background 为 97/76/83/59。将每任务样本上限降到 200、100、50（保留约 51%、37%、22% 数据）时泛化逐步下降；只保留 75% 任务、仍保留 97% 数据时，四项为 86/67/42/53。

**【Analysis】** 这个实验支持保留长尾指令覆盖的价值，但不是一般性的“多样性一定胜过数量”定律：缩小数据通过截断高频任务的样本数，缩窄数据通过删除低频任务，两个操作同时改变采样分布；各项指标也不严格单调。更精确的读法是，本设置删除 25% 指令、仅少 3% 数据，generalization 汇总已从 73 降至 54，接近保留全部指令但只用 51% 数据的 50。

**【Paper】** 附录 Table 13 为机制提供了更直接的证据：取消 ImageNet 初始化使 unseen 76→43；取消历史使 distractor 83→50；改用单峰高斯连续回归使 seen 97→68、distractor 83→37；自回归动作使推理 15→36 ms，却未提高总体表现（background 59→65 是例外）。

**【Analysis】** 连续动作对照只检验了单峰高斯/MSE 头，不能推广为离散分类优于 diffusion 等所有连续多模态策略；FiLM 和 TokenLearner 的必要性也不能仅凭注意力热图作因果证明。

### 5.4 Generalization

![RT-1 在模拟物体和跨机器人数据上的迁移结果（论文 Table 4）](https://pic.hana0721.top/blog/paper-deep-dive-rt1/sim-delta-crop.webp)

**【Paper】** 附录 D.2 的 simulation 数据是通过 real-to-sim 初始化并继续多任务 RL 获得的 518k 条成功抓取轨迹。所有 Table 4 测试都在真实世界：新增物体仅在模拟中有训练动作，已见物体—技能配对成功率 23→87%；这些物体与“move near”等已在真实数据出现的技能组成新配对时，7→33%。这里的 unseen skill 指未见的技能—物体配对，不是发明一种新运动；原有真实物体 92→90%，是小幅下降而非完全不变。

**【Paper】** 跨机器人实验加入 209k 条 Kuka QT-Opt 的成功 **RL** 轨迹，统一动作字段：缺失的 roll/pitch 置零，夹爪开合格式转换，语言统一标为“pick anything”，按 EDR:Kuka=2:1 混合。EDR bin-picking 从 22→39%（+17 个百分点），Kuka-only 控制 EDR 为 0%。附录还说明测试使用相似箱子，并通过加线缆、将夹爪改成灰色使 EDR 外观靠近 Kuka；评测为 72 次抓取。因此这是有动作对齐、目标机器人锚点数据和测试外观匹配的跨平台数据增益，不能读成任意新机器人上的零样本控制。

## 6. 方法分析

### 6.1 为什么有效？

**【Analysis】** 早期语言融合聚焦视觉，TokenLearner 节省注意力预算，离散 action token 统一回归接口，大而多样的数据提供组合泛化。

### 6.2 核心创新

- FiLM-EfficientNet → TokenLearner → Transformer 的紧凑接口。
- 数据采集、背景随机化、simulation model selection 与真实评估形成迭代流程。附录 C.3 的 checkpoint 选择在 551 个模拟任务上进行，用 RetinaGAN 将模拟图像转得更接近真实；目标是模拟分数与真实表现的排序相关，而不是要求两者绝对成功率相等。主实验的这种模拟选模，也应与 §6.3 真正加入模拟训练轨迹区分。
- 分别测量 data quantity、data diversity、heterogeneous source 和 long-horizon。

### 6.3 与已有方法的本质区别

**【Paper】** Gato 缺少语言条件化 image tokenizer 和 TokenLearner；BC-Z 是无历史的 continuous-action policy。RT-1 在 encoder 内融合语言，保留 6 帧历史并用离散 token 建模。

**【Analysis】** RT-1 的 action head 仍是专门的 robot Transformer；RT-2 才把 action token 放回大型 VLM 词表。

### 6.4 关键假设

- 训练与部署的 action spec、相机视角和机器人动力学足够接近。
- 新指令主要是已见 skill 与 object 的新组合。
- 6 帧历史足以处理短期上下文。

## 7. 局限性

### 7.1 作者明确提出的局限

**【Paper】** RT-1 是 imitation learning，难以超过 demonstrator；新指令泛化受限于已见概念组合，不能可靠产生训练中从未出现的新 motion；任务仍以不太灵巧的厨房 manipulation 为主。

### 7.2 自己分析得到的局限

**【Analysis】**

1. 256-bin 均匀量化可能引入控制误差，并依赖部署方正确提供 min/max spec。
2. 非自回归 action slots 牺牲动作维度之间显式的条件依赖。
3. 公开仓库提供网络、训练 agent 及三类 SavedModel checkpoint，但未提供内部完整数据采集与训练流水线，难以复现完整 scaling 曲线。
4. 跨 Kuka/EDR 依赖混合训练，不能推出任意 embodiment 的零样本迁移。

## 8. 启发与研究思考

**【Analysis】** 先设计高效 observation/action token 接口，再考虑把 backbone 做大；评估数据规模必须同时报告 diversity；simulation 与其他机器人数据应作为能力增量，并在目标 embodiment 上保留锚点数据。RT-1 把路线从单任务 controller 推进到了可规模化的 robot policy backbone。
