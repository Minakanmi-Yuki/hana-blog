## 1. 论文概述

**论文名称**：《TraceVLA: Visual Trace Prompting Enhances Spatial-Temporal Awareness for Generalist Robotic Policies》

**作者**：Ruijie Zheng、Yongyuan Liang、Shuaiyi Huang、Jianfeng Gao、Hal Daumé III、Andrey Kolobov、Furong Huang、Jianwei Yang

**论文链接**：[arXiv v3](https://arxiv.org/html/2412.10345v3) · **代码**：[umd-huang-lab/tracevla](https://github.com/umd-huang-lab/tracevla) · **项目主页**：[tracevla.github.io](https://tracevla.github.io/)

![TraceVLA 总体架构：原始观测、叠加轨迹的观测、分隔 token 与动作 token（论文 Figure 1）](https://pic.hana0721.top/blog/paper-deep-dive-tracevla/tracevla-overview.webp)

### 一句话总结

**【Paper】** TraceVLA 不把一串高度相似的历史图像直接塞进 VLA，而是用 Co-Tracker 找到运动中的点，把它们的轨迹画在当前图像上，再将“原图 + 轨迹图”作为多模态提示输入模型。这样，VLA 可以同时看到清晰的当前状态和紧凑的历史运动线索。

### 核心贡献

**【Paper】**

1. 提出 Visual Trace Prompting：用稠密点跟踪与 active-point 筛选，把图像中可跟踪的历史运动编码为 2D 视觉轨迹；没有把机器人 action vector 本身画进去。
2. 基于 OpenVLA 微调 7B TraceVLA，并用约 150K 条带轨迹标注的机器人操作数据训练；另提供基于 Phi-3-Vision 的约 4B 版本（论文模型表亦写作 4.5B，称 TraceVLA-Phi3）。
3. 在 SimplerEnv 的 137 个配置和 WidowX-250 真实机器人任务上验证，7B 模型在 SimplerEnv 的 overall success rate 为 47.7%，比 OpenVLA 的 40.2% 高 7.5 个百分点；真实 corn pick-place 任务达到 8/10，而 OpenVLA 为 1/10。

## 2. 背景与相关工作

**【Paper】** VLA 将视觉—语言基础模型与机器人动作 token 对齐，具备跨任务、跨物体和跨场景的泛化潜力。但典型 VLA 推理只把当前图像 $o_t$ 映射为动作 $a_t$，模型容易对当前帧做反应式决策，却不知道机械臂刚刚从哪里来、物体如何运动、上一动作是否已经造成遮挡或碰撞风险。

一种直接方案是把 $o_{t-N},\ldots,o_t$ 全部拼接输入。论文认为这些帧通常视觉上高度冗余，额外 image tokens 反而会让模型难以抓住与控制有关的变化。TraceVLA 的关键取舍是：保留一张干净原图，再用少量可视化轨迹表达运动历史。

**【Analysis】** 这不是给 VLA 增加一个新的 3D state encoder，而是把 temporal grounding 转换成视觉编码器擅长的“几何图形识别”问题，因此可以复用 OpenVLA 的 backbone 和动作头。

## 3. 问题定义

**【Paper】** 给定当前观测 $o_t$、最近 $N$ 帧历史 $\mathbf h_t=(o_{t-N},\ldots,o_t)$ 与语言任务 $l$，模型需要输出机器人动作 $a_t$：

$$
\hat a_t = \pi_\theta(o_t,\; \operatorname{Trace}(\mathbf h_t),\; l).
$$

- **Observation**：RGB 图像；训练和 WidowX 实验使用固定第三人称视角，真实机器人图像为 $256\times256$。
- **Trace**：从 $K\times K$ 网格点开始，用 Co-Tracker 跨 $N$ 帧跟踪，再按论文定义保留运动总量超过阈值 $\kappa$ 的点，随机采样 $M$ 条轨迹。
- **Action representation**：沿用 OpenVLA 的离散 action token。官方 `ActionTokenizer` 将每个连续动作维度量化到 256 个 bin，再映射到词表末端 token。
- **Embodiment / tasks**：SimplerEnv Google robot 仿真与 WidowX-250 真实桌面操作；任务涵盖 pick-and-place、抽屉、软物体和推扫等操作。

## 4. 方法

### 4.1 Overall Architecture

![Visual Trace 生成：Co-Tracker 跟踪网格点、筛选 active points，并将轨迹叠加到当前观测（论文 Figure 2）](https://pic.hana0721.top/blog/paper-deep-dive-tracevla/tracevla-trace-generation.webp)

**【Paper】** 数据流只有一句话：历史图像 $\rightarrow$ Co-Tracker 点轨迹 $\rightarrow$ active-point 筛选与采样 $\rightarrow$ 当前图像上的彩色 trace $\rightarrow$ 原图和 trace 图之间插入 separator token $\rightarrow$ VLA 预测动作 token。

### 4.2 核心模块

#### Active-point visual trace

- **输入**：长度为 $N$ 的图像窗口和 $K\times K$ 网格点。
- **中间模块**：Co-Tracker 输出每个点的 $(x,y)$ 序列；计算相邻帧位移 $\Delta p_{t'}=|p_{t'+1}-p_{t'}|_1$，将总位移超过 $\kappa$ 的轨迹标为 active。
- **输出**：随机采样的 $M$ 条轨迹，绘制在 $o_t$ 上，并在末端画方向箭头。
- **为什么需要**：以显著运动筛出可能与操作有关的点，减少静态背景干扰。它没有物体语义或接触点识别器，移动背景、相机运动也可能被选中，静止的目标物也可能被过滤。

**【Paper】** 离线标注使用 $K=40,M=5,N=6$。**【Code】** 本次核对 [commit d5454af](https://github.com/umd-huang-lab/tracevla/tree/d5454af9ebe51e996005e13061ac3f6964e2923f)：`TraceProcessor` 使用 30×30 网格、10 帧跟踪缓存，默认最多绘制 15 步轨迹，每 25 步 dense re-query。其筛选量是**相邻帧 L1 位移的均值大于 1 像素**，而非固定阈值下的总位移；只有候选点数严格大于 5 才采样 5 点，正好 5 点也会 fallback。返回的 `pred_visibility` 未参与筛选，因此 `has_trace` 不代表轨迹已经通过遮挡可靠性验证。

#### 双图像输入与 trace dropout

叠加轨迹可能遮住夹爪或目标物，因此模型同时接收原始图像和 trace 图，并用特殊 separator token 分开。训练时以概率 $\alpha$ 将 trace 图替换回原图并移除 trace 提示，使模型学习缺少轨迹时的输入。代码 `RLDSBatchTransform` 默认 `random_drop_rate=0.2`；fallback 仍输入两张相同原图 `[image, image]`，并不是回到单图 OpenVLA 的全部计算路径，也不保证恢复到原始 OpenVLA 的性能。

#### VLA 与 action decoder

**【Paper】** TraceVLA 从 OpenVLA 7B 微调；TraceVLA-Phi3 以 4B Phi-3-Vision 为 backbone，并在 Open-X-Embodiment 上采用与 OpenVLA 类似的预训练配方。模型仍然由 vision encoder、projector、语言模型和 action-token head 构成，创新集中在输入提示而不是更换 action policy。

**【Code】** 仓库中的 `prismatic/models/vlas/openvla.py` 提供 action-token 生成与按 `q01/q99` 反归一化的基础实现；Simpler wrapper 实际通过 `AutoModelForVision2Seq(..., trust_remote_code=True)` 加载模型包，不能把这个本地单图函数直接当作双图部署的完整入口。`ActionTokenizer` 名义配置为 256 bins，具体使用 256 个边界和 255 个区间中心，末端编号裁剪到最后中心。

### 4.3 关键公式

#### Active-point 筛选

$$
\Delta p_{t'}=\left\|p_{t'+1}-p_{t'}\right\|_1,
\qquad
\hat{\mathcal P}=\left\{p\in\mathcal P\mid\sum_{t'=t-N}^{t-1}\Delta p_{t'}>\kappa\right\}.
$$

$p$ 是一条点轨迹，$\mathcal P$ 是所有网格点轨迹，$\hat{\mathcal P}$ 是过滤后的 active points。这个公式把“运动”作为历史信息的稀疏性先验。

#### VLA action-token 目标

$$
\mathcal L(\theta)=-\sum_{j=1}^{d_a}\log p_\theta(y_{t,j}\mid o_t,\operatorname{Trace}(\mathbf h_t),l,y_{t,<j}),
$$

其中 $y_{t,j}$ 是第 $j$ 个离散动作 token，$d_a$ 是动作维度；这是动作自回归监督的概括。**【Code】** `RLDSBatchTransform` 先屏蔽 prompt 标签；`base_strategy.py` 的默认 `action_token_only` 还会将 softmax 的候选词表裁成 **256 个动作 token**，并忽略范围外标签。这不只是“只在动作位置求 loss”，还改变了归一化分母；不能与全词表交叉熵加位置 mask 混为一谈。

### 4.4 Training

**【Paper】** 轨迹标注来自 BridgeData-v2、Google RT-1 robot 数据以及自采 WidowX-250 演示，总量约 150K **机器人轨迹**；其中自采部分为 4 个训练任务各 30 条，共 120 条，不是全部 150K 都由作者重新遥操作采集。为降低离线标注成本，训练阶段把 demonstration 切成重叠的 $2N$ 段，每段只做一次 $K\times K$ dense tracking，以便为窗口内各时刻提取历史轨迹。VLA 在时刻 $t$ 消费的是截至当前的 trace，并非让策略读取未来执行结果；但离线 Co-Tracker 在整段视频上求轨迹与部署时只用已观测历史的计算条件并不完全相同。7B 与 4B 模型都在基础 VLA 上额外微调 5 个 epoch。

**【Code】** `vla-scripts/train.py` 通过 `get_vla_dataset_and_collator` 构造 RLDS 数据集；配置项包含 Open-X 数据根目录、FSDP/多 GPU 训练和 action-token-only loss。官方 README 给出的 TraceVLA 训练命令是 8 节点、每节点 8 GPU 的 `torchrun`。

### 4.5 Inference

**【Paper】** 推理初期先用普通 prompt；有足够历史后，第一次运行 dense $K\times K$ tracking 找到 active points，之后只跟踪这 $M$ 个点。由于 Co-Tracker 约 30–40 步后可能丢失轨迹，系统会周期性 dense re-query，再用当前帧的 trace 图预测动作。

**【Code】** `TraceProcessor.process_image` 在 `begin_track_step` 前返回原图；成功跟踪后保留最近 `window_size` 个 trace，并用 `_visualize_trace` 绘制彩色线段和箭头。`tracevla_simpler.py` 在 trace 无效时切换到普通 prompt，在有效时将 `[image, image_overlaid]` 送入 processor。

**【Code】** 公开 Simpler wrapper 还存在会影响直接运行的问题：`start_episode` 传入 `TraceProcessor(cotracker_model=...)`，但构造器参数叫 `cotracker_model_path`；初始化另一次 Co-Tracker 时又写死作者机器上的 checkpoint 绝对路径。README 的轨迹标注数据下载仍标为 coming soon。因而本文只确认静态实现与这些接口缺口，不宣称照抄仓库即可复现论文表格。

**【Analysis】** TraceProcessor 在模型外生成提示，便于迁移到其他 VLA；但仍需适配双图接口、separator 和微调数据，不能等同于给任意未训练 VLA 随手画线即可获得同样收益。

## 5. 实验

### 5.1 Experimental Setup

**【Paper】** 仿真使用 SimplerEnv 的 visual matching 与 variant aggregation 两种设置，覆盖 Move Near、Pick Coke Can、Open/Close Drawer 三个任务和 137 个环境配置；真实评测使用固定第三人称相机的 WidowX-250：先比较 4 个主实验任务，再增加 4 个未见任务。主实验中的 corn→pot 本身也未出现在本地微调集，训练对应的是 eggplant→pot，因此不能把前四项统一称为 seen tasks。137 是摘要和实验节口径，引言另写 131，本文不将它解释为 137 个不同技能。

![SimplerEnv 与真实机器人评测中的 TraceVLA / OpenVLA 平均结果（论文 Figure 3）](https://pic.hana0721.top/blog/paper-deep-dive-tracevla/tracevla-simplerenv-results.webp)

基线包括 OpenVLA、OpenVLA-Phi3、Octo-Base 和 RT1-X。指标为任务成功率；variant aggregation 额外改变相机姿态、光照、背景、干扰物和桌面纹理。

### 5.2 Main Results

**【Paper】** SimplerEnv 的关键结果如下：

| 模型          |        Visual Matching |    Variant Aggregation |   Overall |
| ------------- | ---------------------: | ---------------------: | --------: |
| OpenVLA       |     47.1 / 15.3 / 49.5 |     54.0 / 52.8 / 22.5 |     40.2% |
| TraceVLA      | **53.7 / 28.0 / 57.0** | **56.4 / 60.0 / 31.0** | **47.7%** |
| OpenVLA-Phi3  |     46.1 / 46.7 / 22.5 |     51.9 / 49.7 / 22.2 |     39.9% |
| TraceVLA-Phi3 | **50.4 / 52.2 / 31.0** | **55.0 / 52.4 / 23.2** | **44.0%** |

三列顺序分别是 Move Near、Pick Coke Can、Open/Close Drawer。**【Paper】** TraceVLA 7B 相对 OpenVLA overall 提升 7.5 个百分点，4B 版本相对 OpenVLA-Phi3 提升 4.1 个百分点。overall 是表中六个条件的等权平均，不是按全部 rollout 数加权。7B 的 7.5 个百分点对应约 18.7% 相对提升，不能混写为摘要的“10%”。官方 README 使用另一组任务与数字，也不应混入本表。

![WidowX-250 真实机器人任务上的成功率对比（论文 v3 Figure 6）](https://pic.hana0721.top/blog/paper-deep-dive-tracevla/tracevla-real-results.webp)

**【Paper】** 在未出现在训练集的 pick-place corn 任务上，TraceVLA 成功 8/10，OpenVLA 成功 1/10。附加的 banana、eggplant、battery、push-cloth 四个未见任务也支持新目标和新运动指令上的收益；这里的未见首先指本地微调数据，不证明 OXE 预训练中从未出现相关对象。每项十次量级的结果也不宜写成精确的普适泛化概率。

### 5.3 Ablation Study

![微调、历史帧、visual trace 的消融对比（论文 v3 Figure 7）](https://pic.hana0721.top/blog/paper-deep-dive-tracevla/tracevla-ablation.webp)

**【Paper】** 消融回答了三个问题：

- 只在同一小数据子集上继续微调并不能解释收益：OpenVLA 仅提升 1.1 个百分点，OpenVLA-Phi3 反而下降 0.3 个百分点。
- 把 6 张历史图像直接拼接给 OpenVLA 使 overall success rate 下降约 6 个百分点。冗余造成干扰是作者的解释，消融没有直接隔离冗余、优化难度和 token 预算等因素；附录 C.2 的两帧历史还带来轻微收益，因此不能推导“历史帧必然无效”。
- Figure 8 的文本轨迹为 42.6%，baseline 为 40.2%，视觉轨迹为 47.7%：文本收益是 2.4 个百分点，视觉相对文本是 **5.1 个百分点**。正文写“额外 6.4%”与图不一致，本文按图中值计算。结果支持这套训练配方下视觉提示更有效，不能证明所有文本轨迹表示都劣于图像。

**【Paper】** Figure 9 中 $N=3,6,9,12$ 的成功率分别为 43.5%、47.7%、47.5%、46.6%。短轨迹 $N=3$ **低于默认 $N=6$**，它仍高于 baseline 40.2%；图中差为 3.3 个百分点，正文写作 3.2%，不能误读成比默认设置又提升 3.2%。附录 C.1 只测试有限的线宽、透明度与颜色组合，结果 47.2%–47.8%，表明这些设置附近不太敏感，而非所有画法都等价。

### 5.4 Generalization

**【Paper】** Figure 4 展示相机方向、干扰物与背景等逐条件结果；正文概括“平均提升超过 20%”，但没有在该段清楚定义聚合分母，本文不把它改写成统一的 20 个百分点或所有环境都提高 20%。真实实验则从三类变化测试泛化：未见物体（banana、battery）、未见目标（eggplant 放到 plate）和未见运动（push cloth）。

![额外 GPU memory 与 inference time 开销（论文 v3 Figure 10）](https://pic.hana0721.top/blog/paper-deep-dive-tracevla/tracevla-costs.webp)

## 6. 方法分析

### 6.1 为什么有效？

**【Analysis】** TraceVLA 同时解决了“历史太长”和“当前状态不能丢”两个矛盾：轨迹线把历史压缩成低带宽几何提示，原图则保留抓取点、纹理和语言 grounding 所需的细节。active-point 过滤减少画面的轨迹杂乱；VLA 仍编码原图与 overlay 两幅完整图像，因此减少轨迹条数 $M$ 并不相应减少视觉 patch token 数。

### 6.2 核心创新

1. **表示创新**：把观测到的历史运动变成可视化轨迹，而非追加 observation frames。
2. **系统创新**：原图 + overlay + separator 只需对现有 VLA 的输入格式做小改动。
3. **工程创新**：dense tracking 只负责发现 active points，之后用稀疏跟踪维持实时性。
4. **鲁棒性设计**：trace dropout 让模型学会在有、无 trace 两种模式下工作。

### 6.3 与已有方法的本质区别

历史帧堆叠增加的是原始视觉上下文，text trace 增加的是坐标 token；TraceVLA 增加的是由视觉 encoder 直接解析的运动几何。**【Analysis】** 这使它不依赖额外的时序 Transformer 或显式 3D state，同时更接近 OpenVLA 已经学会的图像理解路径。

### 6.4 关键假设

- 2D 点轨迹足以表达当前任务所需的主要空间关系；论文没有证明所有接触和深度关系都能由 2D trace 恢复。
- 运动明显的点比静态背景更有控制价值，且随机采样 $M$ 个 active points 不会丢掉关键对象。
- Co-Tracker 在训练与部署相机上能稳定工作；否则模型依赖 dropout 学到的 fallback。
- OpenVLA 的 action tokenizer 与低层控制器已经足够，瓶颈主要来自时空观测而非动作空间。

## 7. 局限性

### 7.1 作者明确提出的局限

**【Paper】** 额外图像和 Co-Tracker 会增加训练显存与推理时间；长 trace 可能遮挡夹爪或物体；Co-Tracker 需要周期性 dense re-query 以避免丢轨迹。作者还提出未来可研究多点空间轨迹预测与 3D point cloud 表示。

### 7.2 自己分析得到的局限

**【Analysis】**

1. active-point 的运动阈值 $\kappa$ 依赖像素尺度、相机视角和动作速度，跨数据集迁移时可能需要重新调参。
2. 随机采样 5 个点并不保证覆盖真正的接触点；快速运动、遮挡、反光或纹理贫乏区域会让 trace 断裂。
3. 轨迹是 2D 投影，无法区分沿视线方向的运动；对堆叠、插入和遮挡严重的任务，2D 线索可能不充分。
4. 代码默认值（例如 grid size 30、窗口 15、每 25 步重绘）与论文中 $K=40,N=6$ 并不完全一致，复现实验时必须锁定 commit、checkpoint 和配置。

## 8. 启发与研究思考

**【Analysis】** TraceVLA 最值得借鉴的不是“画线”本身，而是它把时序建模拆成了一个可插拔的 perception adapter：任何能输出稀疏几何提示的 tracker、光流或 segmentation memory，都可以替换 Co-Tracker，而不必重写 VLA 主体。

后续研究可以沿三个方向展开：

- **从被动轨迹到预测轨迹**：让模型同时预测未来的关键点轨迹，再把预测轨迹作为 action planning 的中间表示。
- **从 2D 到 3D / object-centric trace**：将深度、物体 ID 和接触状态一起画入 prompt，减少视角变化和遮挡造成的歧义。
- **自适应 trace budget**：根据场景运动量动态决定 $M,N$ 和重绘频率，在静态场景省算力、在快速接触阶段保留更多历史。
