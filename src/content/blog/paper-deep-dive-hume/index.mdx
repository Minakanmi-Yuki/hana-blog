## 1. 论文概述

**【Paper】**《Hume: Introducing System-2 Thinking in Visual-Language-Action Model》把 VLA 控制拆成两个异步系统：System 2 是较慢但能反复采样、用 state-action value 选择动作的规划器；System 1 是轻量、快速的 visuomotor policy，负责把尚未完全去噪的动作片段变成流畅控制信号。论文在 3 个仿真环境、3 种真实机器人平台和 21 个真实任务上评估这一设计。

![Hume 双系统总览（论文 Figure 2）](https://pic.hana0721.top/blog/paper-deep-dive-hume/pipeline-crop.8vnnkq28ao.webp)

### 一句话总结

**【Analysis】** Hume 把“是否值得执行”的判断从动作生成中分离出来：System 2 用多次采样换取候选多样性，System 1 用级联去噪换取实时性与精度。

### 核心贡献

**【Paper】**

1. 在预训练 VLA 上增加 value-query head，估计 observation 与候选 action chunk 的 state-action value，并用 Best-of-N 选择。
2. 提出 cascaded dual-system action denoising：System 2 输出长时域、带残余噪声的 chunk，System 1 接力完成局部去噪。
3. 设计低频 System 2 / 高频 System 1 的异步部署机制，使慢思考不会直接牺牲控制频率。
4. 在 LIBERO、SimplerEnv、WidowX、Franka 与 AgiBot G-1 上验证，并报告消融收益。

## 2. 背景与相关工作

**【Paper】** 现有 VLA 往往直接预测动作或 action chunk。Diffusion/flow-matching policy 能表达多模态动作，但采样成本高；单次采样又可能把偶然的坏轨迹交给机器人。纯粹增加采样次数则会降低闭环控制频率。

Hume 借用了 LLM 中 System 1/System 2 的分工：System 2 进行低频、计算密集的候选评估，System 1 进行高频、反应式执行。**【Analysis】** Hume 用学习到的 Q 函数排序候选，并显式保留长时域动作选择。

## 3. 问题定义

**【Paper】** 在时刻 $t$，给定多视角 RGB 图像、自然语言指令和机器人状态：

- **Observation**：$\mathbf{o}_t=(\mathbf{i}_t,\ell_t,\mathbf{s}_t)$。
- **Action**：长度为 $H$ 的连续 action chunk，$\mathbf A_t=[\mathbf a_t,\ldots,\mathbf a_{t+H-1}]$。
- **目标**：从同一观测生成多个候选，选出价值最高者，再以高控制频率输出平滑动作。
- **Embodiment**：仿真中的 WidowX/Google robot，以及真实 WidowX、Franka、AgiBot G-1。
- **奖励**：离线 RL 中每条 episode 的最后 3 个 transition 奖励为 $+1$，其余为 $0$。

**【Code】** 官方仓库提供 LIBERO 评估与训练代码，同时发布 Hume-System2 权重；README 标注真实世界和 SimplerEnv 评估代码仍未发布。

## 4. 方法

### 4.1 Overall Architecture

**【Paper】** System 2 读取 observation，经 VLM、flow-matching action head 和 value-query head 得到 $N$ 个不同噪声水平的候选；最高 Q 值的长 chunk 被切成短片段，送入 System 1 的 DINOv2-small + lightweight transformer 做连续去噪。数据流见 Figure 2。

### 4.2 核心模块

#### System 2：候选动作生成

**【Paper】** action denoising head 学习 $p(\mathbf A_t\mid\mathbf o_t)$。从高斯噪声 $\mathbf A_t^0$ 出发，用 flow vector field $\mathbf v_\theta$ 积分到不同终点 $1-(n-1)\xi$，得到既有完全去噪动作、也有残余噪声的候选。

#### Value-query head

**【Paper】** VLM 输入序列末尾附加可学习 query token $\mathbf q_t$。图像/语言条件得到的 query 表征与候选 action chunk 共同用于 critic 评分；Cal-QL 的 actor 辅助离线训练和 Bellman backup，实际候选仍由 S2 flow head 生成，不由这个 actor 执行。选择规则为 $Q_\theta(\mathbf q_t,\mathbf A_t)$：

$$
\mathbf A_t^{\tau^*}=\arg\max_{n\in\{1,\ldots,N\}}Q_\theta(\mathbf q_t,\mathbf A_t^{\tau_n}).
$$

![候选 action 与 Q 值的 PCA value map（论文 Figure 3）](https://pic.hana0721.top/blog/paper-deep-dive-hume/pca_map-crop.6m4n18hhsf.webp)

**【Code】** `ValueQueryHead` 实际定义在 `modeling_hume.py`，共享视觉/词嵌入后由单独的 `VQHBackbone` 处理 query。`select_q_actions` 输入图像和语言，候选只取前 `vqh_chunk_size` 步评分；当前接口没有把本体状态显式传入 Q head。`CalQL.get_q_values` 取两个 target critics 的较小值，再做 argmax。因此“评估整段含完整机器人状态的计划”并不是所有配置下都成立。

**【Analysis】** 最后三步的 +1 奖励让 Q 学习折扣终点回报，不是经校准的任务成功概率；它依赖示教结束确实对应完成。PCA 图说明示教附近存在高值区域，既不能证明分布外 Q 校准，也不能因示教不在最高值点就断言没有过拟合。候选经 S1 修改后还未重新评分，所以 Q 选中高值的原始 chunk 不保证 refinement 后价值仍然最高。

#### System 1：级联动作去噪

**【Paper】** System 2 的 chunk 被切成 $K=H/h$ 个子 chunk。System 1 输入当前视觉、机器人状态和带残余噪声的子 chunk，从 $\omega=0$ 积分到 $\omega=1$，输出最终动作。

**【Code】** FastVisuoExpertModel 使用 DINOv2-small 和轻量 transformer；HumePolicy.select_action 先调用 s2_model.sample_actions，再由 value_query_head.select_q_actions 选中，最后调用 s1_model.sample_actions。HumePolicy.infer 维护 action_plan 队列和 history_state。

### 4.3 关键公式

#### Flow matching

**【Paper】** §3.1 同时写了“噪声到数据”的插值 $A^\tau=\tau A+(1-\tau)\epsilon$、正向 Euler 积分，以及相反方向的目标 $\epsilon-A$，三者符号不自洽。若沿该插值从 0 积分到 1，正确导数应是 $A-\epsilon$。

**【Code】** 为避免照抄这个符号冲突，下面采用官方 `modeling_hume.py` 实际使用的“数据到噪声”时间 $s$：

$$
x_s=(1-s)A+s\epsilon,\qquad
\mathcal L_{FM}=\mathbb E\|v_\theta(x_s,s,o)-(\epsilon-A)\|_2^2,
\qquad
x_{s+\Delta s}=x_s+\Delta s\,v_\theta(x_s,s,o),\quad \Delta s<0.
$$

完整去噪从 $s=1$ 向 0 积分，默认 10 步；与论文正向时间通过 $s=1-\tau$ 对应。`time_temp`、`theta2` 会改变实际积分起止，当前候选代码改变起始时间并独立重采高斯初值，不宜将其说成严格复现论文式（1）的固定起点、不同终点积分。

#### Cal-QL value objective

$$
\min_\theta\;\alpha\mathcal R(\theta)+\frac12\mathbb E\left[(Q_\theta(\mathbf q_t,\mathbf A_t)-\mathcal B^\pi\bar Q(\mathbf q_t,\mathbf A_t))^2\right].
$$

**【Paper】** $\mathcal R$ 抑制分布外动作过估计，同时用行为策略回报作校准下界，避免纯保守惩罚把所有候选压得过低；$\bar Q$ 是延迟 target network。**【Code】** 实现对策略采样动作的 Q 与数据中的 Monte Carlo return 取最大值，再构造保守项。这是带下界的价值学习约束，不是对候选真实性或安全性的认证。

#### Cascaded denoising

$$
\widetilde{\mathbf A}_{t+kh}^{\omega}=\widetilde{\mathbf A}_{t+kh}^{\tau^*}+\int_0^\omega\mathbf v_\theta(\widetilde{\mathbf A}_{t+kh}^{\omega},\widetilde{\mathbf o}_{t+kh})d\omega.
$$

**【Analysis】** System 1 的初值是被选中的“半成品”动作，视觉/状态则更新到执行子段的时刻。**【Code】** S1 训练时在 S2 预测子段 $B$ 与示教子段 $A$ 之间构造 $(1-s)A+sB$，回归 $B-A$，并可对 $B$ 做滑窗/扰动；推理从传入的 $B$ 逆向积分。它是另一个条件生成器学习从粗动作到示教动作的映射，不是继续同一个 S2 ODE，也不受保留原轨迹拓扑或 Q 排序的约束。

### 4.4 Training

**【Paper】** 训练分两阶段：第一阶段训练 VLM backbone 与 System 2 action head；第二阶段冻结这两部分，从头训练 System 1 和 value-query head。Q head 使用离线 demonstrations、稀疏终点奖励和 Cal-QL；System 1 使用 flow-matching loss。

### 4.5 Inference

**【Paper】** 示例中 System 2 以 4 Hz 生成 $N=5$ 个长度 $H=30$ 的候选，System 1 以 6 Hz 处理长度 $h=15$ 的子 chunk，作者把每次生成 15 个动作乘以 6 次调用/秒，称为 90Hz 动作控制；这不是每秒 90 次视觉重规划。论文的异步共享队列描述与具体时间预算也应分开看：两段 S1 按 6Hz 需约 333ms，而 S2 的 4Hz 是 250ms，不能据此声称每次必定在下一份 S2 到来前消耗完整 30 步。实际丢弃旧计划/对齐延迟的策略需要部署实现确定。

## 5. 实验

### 5.1 Experimental Setup

![Hume 实验平台：WidowX、AgiBot G-1 与 Franka（论文 Figure 4）](https://pic.hana0721.top/blog/paper-deep-dive-hume/exp_setup-crop.4clmhqwr82.webp)

**【Paper】** 实验覆盖 SimplerEnv 和 LIBERO 仿真，以及 WidowX、Franka、AgiBot G-1 三个平台；真实测试共 21 个 manipulation tasks，包含视角/纹理/光照变化、未见物体、可变形物体、工具使用和 humanoid 控制。

### 5.2 Main Results

**【Paper】** LIBERO 平均成功率为 **98.6%**，四个 suite 均排名第一；LIBERO-Long 为 **96.7%**，高于 $\pi_0$ 的 85.2%。**注意指标口径：** SimplerEnv WidowX 报告的 **72.6%** 是四任务各自“Grasp”和“Success”共八列的均值，混合了抓取阶段完成与全任务完成；只取四个最终 Success（58.0、66.7、45.5、72.8）重新平均是 **60.75%**，不能将72.6%写成四任务完整成功率。Google robot 的 variant aggregation 平均 **74.1%**、visual matching 平均 **78.7%**。

![WidowX 真实任务结果（论文 Figure 5）](https://pic.hana0721.top/blog/paper-deep-dive-hume/exp_widowx-crop.2ksnmudedl.webp)

**【Paper】** 论文主结果报告 WidowX 真实任务平均91%，相对 $\pi_0$ 提升 12 个百分点；Franka 平均 87%，相对 $\pi_0$ 提升 14.75 个百分点。AgiBot 的 Fold Shorts 为88%，Pour Water 为82%。但附录 C.2 明确说复杂任务同时统计抓取、中间子任务和总体完成；Figure 6 的 Franka 平均87%对应四组图示评分，而非清晰列出七任务等权最终成功率。真实每项试验分母没有完整报告，Figure 7 消融中 WidowX/Franka 完整模型又分别标为86%/91%，与主图91%/87%不一致。因此这些是真实实验原报汇总值，不能跨图当作同一组精确可复算的终局成功率。

### 5.3 Ablation Study

![Hume 真实平台消融结果（论文 Figure 7）](https://pic.hana0721.top/blog/paper-deep-dive-hume/ablation_bar-crop.mta7dfn1.webp)

**【Paper】** LIBERO 平均成功率从完整模型的 98.6% 降至：去掉 cascaded denoising 为 95.9%，去掉 repeat sampling 为 93.8%，去掉 System 1 为 89.8%，去掉 value-query head 为 84.9%。SimplerEnv WidowX 对应平均值为 72.6%、68.7%、65.6%、61.6%、56.3%。

**【Paper】** 这些删除实验也改变候选分布：去 cascaded denoising 让 S2 完全去噪全部候选；去 S1 会直接执行可能仍带噪的候选；去 Q head 从五个不同噪声候选中随机选一个。因此大幅下降既反映模块作用，也包含直接下发残余噪声或随机选噪声水平的损害，不能当成与等计算预算的强单系统基线完全隔离的比较。

**【Analysis】** value head 决定“选谁”，repeat sampling 决定“有没有可选项”，System 1 决定“选中的半成品能否被精确执行”。

### 5.4 Generalization

**【Paper】** 泛化测试覆盖环境外观、相机位姿、语言描述、物体与布局变化，以及在不同 embodiment 分别训练/适配后的真实部署。**【Analysis】** WidowX 标作零样本设置，Franka/AgiBot 有各自示教训练，不能合并为一个权重对未见机器人直接零样本迁移；论文没有证明完全未见任务语义上的 zero-shot planning。

## 6. 方法分析

### 6.1 为什么有效？

**【Analysis】** flow-matching policy 的单次输出包含采样噪声。Hume 先保留多样性，再用 Q head 把它转化为候选间的可选择性；System 1 避免把全部去噪步骤堆到慢速 VLA 上。System 2 解决选择问题，System 1 解决执行问题。

### 6.2 核心创新

1. **Value-guided repeat sampling**：Q 值对 action chunk 排序。
2. **Cascaded action denoising**：把未完成的 flow trajectory 作为快策略输入。
3. **Asynchronous dual frequency**：慢模块只在重规划时运行，快模块持续消费动作队列。

### 6.3 与已有方法的本质区别

**【Analysis】** 相比普通 Best-of-N，候选来自不同 flow 时间终点；相比 diffusion policy refinement，Hume 额外学习离线 RL value function；相比单体 VLA，规划频率和执行频率可以独立设置。

### 6.4 关键假设

- **【Paper】** Q head 能从离线 demonstration 学到可靠的 state-action value。
- **【Analysis】** 候选 action 的 Q 排序在分布外状态仍然有效。
- **【Analysis】** System 1 能在下一个 System 2 chunk 到来前完成去噪。

## 7. 局限性

### 7.1 作者明确提出的局限

**【Paper】** 论文 §5 明确有 “Conclusion and Limitations”：候选本身质量限制了 best-of-N 上限；Q 值尚未很好地与语义对齐；当前所谓 System-2 thinking 仍是简单候选搜索，树搜索、自我修正和更复杂 RL 留待未来。这也说明论文没有实现语言 CoT、反事实世界模型规划或开放式自我反思。

### 7.2 自己分析得到的局限

1. Q head 依赖稀疏终点奖励，可能难以细致估计中间状态的可恢复性。
2. 当前公开 `select_action` 顺序调用 N 次 S2，每次内部重新编码前缀并建 KV cache，确有明显额外成本；这是该实现行为，批量候选和跨候选复用前缀可改变成本比例，不能把严格 N 倍写成方法固有定律。
3. critic 偏差可能反过来影响候选选择，Cal-QL 只能缓解而不能消除耦合风险。
4. 论文分平台参数、训练脚本默认值和实际 checkpoint 配置不同；加上异步调度与部分结果口径未完整复现，必须锁定配置、评测分母和数据处理流程。

## 8. 启发与研究思考

**【Analysis】** Hume 给出的可迁移范式是“粗粒度候选 + 细粒度执行”。后续值得追问：能否用 uncertainty-aware value 让 $N$ 自适应？能否让 System 1 预测执行风险并主动请求 System 2？能否把高层 subgoal 或 world model rollout 接入 value-query head，减少对稀疏终点奖励的依赖？
