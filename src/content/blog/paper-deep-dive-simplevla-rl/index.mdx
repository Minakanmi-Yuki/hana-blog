## 1. 论文概述

**【Paper】**《SimpleVLA-RL: Scaling VLA Training via Reinforcement Learning》研究一个很具体但重要的问题：当 VLA 已经通过 SFT 学会基本操作后，能否像 Large Reasoning Model 一样，仅用环境最终成败的奖励继续扩展能力？作者在 veRL 上实现了 SimpleVLA-RL，并将 OpenVLA-OFT 作为主要 backbone。

![SimpleVLA-RL 论文 Figure 1：数据稀缺、仿真与实机结果、pushcut 行为及泛化实验总览](https://pic.hana0721.top/blog/paper-deep-dive-simplevla-rl/overview_v4.2h91oy30jh.webp)

### 一句话总结

**【Analysis】** SimpleVLA-RL 用并行仿真中的成败反馈，优化一个已由 SFT 冷启动的离散动作策略。组内同时出现成功与失败时，GRPO 为整条成功轨迹提供正优势、失败轨迹提供负优势；这能支持超出当前任务示范的行为探索，但不意味着 SFT 本身完全没有泛化能力，也不意味着所有动作都能获得准确的因果 credit。

### 核心贡献

**【Paper】**

1. 在 veRL 中加入 VLA 专用的交互式 trajectory sampling、并行多环境渲染、分布式训练与推理，形成端到端在线 RL 框架。
2. 使用不依赖任务过程奖励的二值 outcome reward，并提出 dynamic sampling、higher rollout temperature 和 clip higher 三种探索增强策略。
3. 在 LIBERO、RoboTwin 1.0/2.0 上显著超过 SFT 基线；只用每个任务一条示教时，LIBERO-Long 从 17.3% 提升到 91.7%。
4. 仅用仿真数据训练的策略在真实双臂 Piper 上平均成功率由 17.5% 提升到 38.5%。
5. 观察到 `pushcut`：策略在没有示教该动作的情况下，学会用推动替代抓取-搬运-放置。

**【Paper】** 首先明确 backbone：本文称作 OpenVLA-OFT 的版本只保留 **parallel decoding + action chunking**，以 LLaMA2 词表头和交叉熵替换原版连续 MLP / L1 动作头，且只用单视角；LIBERO 还移除 proprioception。作者重新做任务 SFT，不能直接复用原版 OFT checkpoint。因此这里验证的是改造后的 categorical policy 在线 GRPO，不是把原版 OFT 连续动作原封不动送进算法。

## 2. 背景与相关工作

**【Paper】** 现有 VLA 通常遵循“多模态预训练 → 大规模 SFT”的路线。扩展 SFT 需要昂贵的人类遥操作轨迹，而且训练分布往往绑定于固定物体、场景和任务组合，导致长时程与分布外泛化较弱。LLM 的在线 RL 可以通过随机采样和规则奖励探索多条推理路径，但 VLA 的 rollout 必须真正执行动作、刷新视觉观测和 proprioception，成本更高。

**【Analysis】** 论文的切入点不是设计新的 action decoder，而是把 VLA 的 action token 当作可以采样、计算 log-probability 的离散决策单元。这样 PPO/GRPO 的“概率比率—优势—策略更新”链条可以直接复用，同时把环境交互补到 LLM rollout 缺失的闭环部分。

## 3. 问题定义

**【Paper】** 在时间步 $t$，状态由视觉观测、机器人本体状态和语言指令组成：

$$s_t=(o_t^{\mathrm{vis}},o_t^{\mathrm{prop}},l_{\mathrm{task}}).$$

策略输出长度为 $K$ 的 action chunk。每个 action 是 $d$ 维连续控制量（例如末端位姿增量与夹爪），由本文改造版的 action tokenizer 量化为离散 tokens。环境执行 chunk 后返回新观测，直到成功、失败或达到最大步数。

SimpleVLA-RL 使用 trajectory-level outcome reward：

$$R_i=\begin{cases}1,&\text{trajectory }i\text{ 完成任务},\\0,&\text{otherwise.}\end{cases}$$

**【Code】** `verl/workers/rollout/rob_rollout.py` 的 `RobotwinEnvWrapper` 负责 `initialize`、`step` 和 `eval_success`；`verl/utils/reward_score/evaluation_utils/libero_util/` 与 RoboTwin 环境的 `check_success` 将环境状态转换为 0/1 结果。训练时该标量被写到有效 action token 的末端位置，再由 GRPO 计算组内优势。

## 4. 方法

### 4.1 Overall Architecture

SimpleVLA-RL 由四个协同部分组成：OpenVLA-OFT policy、veRL actor/rollout worker、并行环境池和 reward manager。每轮先将同一个任务和初始场景复制 $G$ 份，在不同环境实例中采样；每个环境执行 action chunk 后重新编码图像与 proprio，再生成下一个 chunk。

**【Paper】** 论文的整体数据流是：SFT policy → temperature sampling → 多环境闭环 rollout → 任务成功判定 → group-relative advantage → clipped policy update。

**【Code】** `verl/trainer/ppo/ray_trainer.py` 串起 dataloader、rollout、reward、advantage 与 checkpoint；`verl/workers/actor/dp_rob.py` 计算 action-token log-probability 和 policy loss；`verl/workers/rollout/rob_rollout.py` 用线程池并行初始化和推进环境。仓库支持 LIBERO、RoboTwin 1.0/2.0，并提供 OpenVLA 与 OpenVLA-OFT 的实现。

### 4.2 核心模块

#### 交互式 VLA Rollout

- **输入**：任务语言、当前 RGB/proprioception、旧策略 $\pi_{\theta_{old}}$。
- **中间模块**：action-token sampling、chunk decoder、环境 `step`、done 过滤。
- **输出**：包含每个 action token 概率、状态和最终成功标记的完整 trajectory。
- **必要性**：LLM 一次生成完整文本；机器人动作会改变世界，下一次决策必须依赖新观测。

**【Code】** 当前 `rob_rollout.py` 的 RoboTwin 路径使用 thread pool，LIBERO 路径则以独立 process 和 queue 推进环境；两者都维护 active 集合，在策略批量生成与环境执行之间同步。组内重复同一 `task_id / trial_id`（RoboTwin 还含 `trial_seed`），主要通过动作采样产生不同轨迹，不能把同一任务的任意不同难度场景混成相同初态的 GRPO group。

#### 二值 outcome reward

**【Paper / Code】** 论文将终局成败传播到整条轨迹；代码实际只在最后一个有效 token 存入 0/1，先沿 token 维求和得到一次 trajectory reward，再把**标准化优势**广播到所有有效 token。不是每执行一个动作都再领一次 1，否则会隐含偏爱更长轨迹。它省掉距离等过程奖励，但每项任务的 success predicate 仍由模拟器定义；“奖励形式通用”不等于判定器无需任务规则。

#### 三种探索增强

1. **Dynamic sampling**：丢弃一组全成功或全失败的样本，持续采样直到组内同时存在成功与失败，避免 GRPO 的标准差为 0、优势消失。
2. **Clip higher**：把 importance ratio 的上界从 $1.2$ 提高到 $1.28$，允许低概率 action token 更快增权。
3. **Higher rollout temperature**：采样温度从 $1.0$ 调到 $1.6$，扩大动作轨迹的多样性。

![SimpleVLA-RL 的 clip higher 消融（论文 Figure 3b）](https://pic.hana0721.top/blog/paper-deep-dive-simplevla-rl/vla_ablation_1_clip_higher.8hh7tocme5.webp)

### 4.3 关键公式

对同一初始任务采样 $G$ 条 trajectory，组内优势为：

$$\hat A_i=\frac{R_i-\operatorname{mean}(R_{1:G})}{\operatorname{std}(R_{1:G})+\epsilon}.$$

其中 $R_i\in\{0,1\}$ 是整条轨迹奖励，$\epsilon$ 防止数值除零；在默认 $G=8$ 下，代码以成功比例 $[0.1,0.9]$ 过滤，恰好保留 1–7 条成功的组。采样会继续读取下一批场景直到凑齐有效 batch 或当轮数据耗尽；不是无条件反复尝试同一初态直到一定成功。

**【Analysis】** 假设一个初态下各次 rollout 独立且成功概率为 $p$，组被保留的概率为 $1-p^G-(1-p)^G$。$G=8,p=0.01$ 时只有约 7.7% 的组有效；动态采样提高了已用于更新的 batch 的信息量，却没有免费解决稀有成功问题，而且使更新场景分布偏向尚未全会、也不是完全不会的初态。

去掉 KL reference model 后，论文 Eq. (11) 的目标为：

$$
\mathcal J(\theta)=\mathbb E\left[\frac1G\sum_{i=1}^G\frac1{|a_i|}\sum_t
\min\left(r_{i,t}\hat A_i,\operatorname{clip}(r_{i,t},1-\varepsilon_{low},1+\varepsilon_{high})\hat A_i\right)\right],
$$

$$
r_{i,t}=\frac{\pi_\theta(a_{i,t}\mid s_{i,t})}{\pi_{\theta_{old}}(a_{i,t}\mid s_{i,t})},\quad
\varepsilon_{low}=0.2,\;\varepsilon_{high}=0.28.
$$

**【Analysis】** 对正优势，ratio 超过 1.28 后该样本的 clipped surrogate 不再奖励进一步增大；对负优势，低于 0.8 后不再奖励继续下降。它是目标函数的截断，不是保证所有更新后概率比都落在 $[0.8,1.28]$ 的硬约束。放宽上界允许采样到的成功 token 获得更大增权空间，但本身不会生成新动作；探索仍来自温度采样与环境交互。去掉 reference KL 减少计算，也移除了一个固定参考约束。

**【Code / Analysis】** 更新时同样对 256 个动作 logits 除以 rollout 温度，再重算新旧 categorical log-prob；否则分子分母会对应不同策略。每个标量动作维度 token 独立进入 ratio 和 clipping，整条 trajectory 共享优势；这不是完整 chunk 或整条轨迹联合概率的 importance ratio，也没有定位某个 token 对最终成败的因果贡献。

### 4.4 Training

**【Paper】** 主要实验先对 OpenVLA-OFT 做 SFT，再在相同任务的仿真场景中在线 RL。训练使用 8 张 A800 80GB，学习率 $5\times10^{-6}$、batch size 64、每个初态采样 8 条 trajectory。256 指动作输出的**类别词表大小**，不是一次预测 256 个时间步或 256 个 token；LIBERO 每次预测 8 个 7 维动作（56 个 token），RoboTwin 为 25 个 14 维动作（350 个 token）。LIBERO 最大交互 512 步，RoboTwin 根据任务使用 200/400/800 步。训练采样温度为 1.6，评估使用 greedy decoding，每个基准重复评估三次；原文未将其明确表述为三次独立训练种子。正文报告 full-parameter RL，不能把原版 OFT 的 LoRA 训练成本套到这里。

## 5. 实验

### 5.1 Experimental Setup

**【Paper】** 实验覆盖 LIBERO（Goal、Spatial、Object、Long）、RoboTwin 1.0、RoboTwin 2.0，并在两台 AgileX Piper 上做真实部署。LIBERO 每个任务评估 50 个 held-out 场景；RoboTwin 2.0 选择 12 个任务，覆盖约 112–637 步的短、中、长和超长时程，每个任务评估 100 个场景。

**【Paper】** 数据口径分别为：LIBERO 每套 500 条示范做 SFT，再在对应 500 个场景上 RL；RoboTwin 1.0 只评 4 项任务，每任务 50 条 SFT 示范、100 个 RL 场景；RoboTwin 2.0 选择的 12 项任务每项 1,000 条 SFT 示范、1,000 个 RL 场景。RoboTwin 使用单任务适配，平均分不能解释成一个共同策略掌握了全部 12 项。RL 场景数也不等于总 rollout 数，同场景会被反复采样。

### 5.2 Main Results

| Benchmark               | OpenVLA-OFT SFT | + SimpleVLA-RL |  提升 |
| ----------------------- | --------------: | -------------: | ----: |
| LIBERO 平均             |            91.0 |       **99.1** |  +8.1 |
| LIBERO-Long             |            86.5 |       **98.5** | +12.0 |
| RoboTwin 1.0 平均       |            39.8 |       **70.4** | +30.6 |
| RoboTwin 2.0（12 任务） |            38.3 |       **68.8** | +30.5 |

**【Paper】** 在 RoboTwin 2.0，SimpleVLA-RL 的 68.8% 平均成功率高于 $\pi_0$ 的 49.2% 与 RDT 的 33.3%；短时程任务平均从 21.3% 提升到 64.9%，中时程从 47.1% 到 72.5%，长/超长时程从 46.5% 到 69.0%。

**【Analysis】** 这些差值均为百分点。最可靠的比较是同一改造 backbone 的 SFT → RL；其他基线仅做 SFT，而本方法额外使用在线模拟器交互，因此排名同时包含训练范式与数据预算差异。RoboTwin 2.0 的 Handover Mic 上 RL 为 89.2%，仍低于 $\pi_0$ 的 96.0%；RoboTwin 1.0 Shoe Place 的 59.3% 与 DP3 持平。平均提升不等于逐任务全胜。

![Dynamic sampling 消融（论文 Figure 3a）](https://pic.hana0721.top/blog/paper-deep-dive-simplevla-rl/vla_ablation_3_dynamic_sampling.5q85llqihp.webp)

![Higher rollout temperature 消融（论文 Figure 3c）](https://pic.hana0721.top/blog/paper-deep-dive-simplevla-rl/vla_ablation_2_temperature_higher.1lck9htccc.webp)

**【Paper】** 三个策略分别缓解不同问题：dynamic sampling 防止无梯度 group，higher temperature 提供更多候选轨迹，clip higher 放宽成功 token 的增权幅度。Figure 3 在 LIBERO-Long 中分别开关各项，标注约 15、10、15 **个百分点**的收益；不是三项贡献可相加，也不是所有基准上都增加 10–15%。横轴是 RL update steps，动态采样会消耗被丢弃的 rollout，图中没有按等环境步数或等 GPU 小时比较，故不能由曲线直接得出样本效率或墙钟加速。

### 5.4 Generalization

**【Paper / Analysis】** Figure 4 在 Spatial、Object、Goal 各展示三个留出任务的设置；后续训练用 9 个任务，评估第 10 个。关键是两条路线都从 §5.1 的 One-Trajectory SFT base 出发，该节每套 10 个任务各用一条示范；§5.2 没有说明为每个留出设置重新移除其冷启动示范。因此这里的 unseen 应严格限定为**后续 SFT / RL 阶段未训练**，不能宣称该任务从未出现在任何训练阶段。它同时检验能力保持和迁移。曲线横轴为 seen-task 成功率，既不是相同训练步数也不是相同算力；SFT 继续用 450 条示范，RL 继续采样场景，证据支持本设置中 RL 比继续 SFT 更少遗忘，而非所有任务与所有 SFT 配方的普遍结论。

## 6. 方法分析

### 6.1 为什么有效？

**【Analysis】** 关键不是“二值奖励足够精细”，而是三个条件同时成立：SFT policy 已经能偶尔成功；仿真环境能快速给出可靠终局标签；每组采样有足够多样性。成功轨迹提供正向 policy gradient，失败轨迹提供相对基线，RL 因而能重排已有动作分布并扩大可行策略集合。

### 6.2 核心创新

**【Paper】** 真正的工程创新是把 VLA rollout 变成 veRL 的一等公民：并行环境渲染、视觉状态刷新、action-token log-probability 对齐和奖励写回都在同一训练循环内完成。算法层面的创新则是把 LLM RL 中的 dynamic sampling、非对称 clipping 和温度调节迁移到机器人控制。

### 6.3 与已有方法的本质区别

**【Analysis】** SFT 优化“复现示教动作”，SimpleVLA-RL 优化“在环境中完成任务”；Diffusion Policy 或连续 MLP action head 没有天然的 token-level categorical probability，而 OpenVLA-OFT 的离散 action token 使 GRPO 可以直接计算 ratio。论文因此没有声称框架已经覆盖 diffusion VLA，仓库 roadmap 也把 flow-matching RL 列为后续工作。

### 6.4 关键假设

- **【Paper】** 初始 policy 必须有非零任务能力，否则采样不到成功轨迹，0/1 reward 的 group advantage 全为零。
- **【Analysis】** 仿真成功判定应匹配真实任务目标，domain randomization 对迁移的帮助需通过实机验证；本文的低绝对成功率不足以证明它普遍充分。
- **【Analysis】** action-token 的概率比率能够代表连续控制变化；当 tokenizer 量化误差或 chunk 很长时，这一假设可能变弱。

## 7. 局限性

### 7.1 作者明确提出的局限

**【Paper】** 失败模式实验显示：没有 SFT（0 条 trajectory）时，五个 RoboTwin 2.0 任务均为 0%，RL 也无法启动；100 条示教平均仅从 7.3% 提升到 25.4%，而 1000 条示教可从 28.2% 提升到 50.4%。这说明在本采样预算下存在能力瓶颈；不能把有限 rollout 中观测为 0% 当成数学上严格零成功概率，也没有一个跨任务通用的数值阈值。

### 7.2 自己分析得到的局限

1. **【Analysis】** 闭环 rollout 仍然昂贵。并行化降低了墙钟时间，却没有消除仿真、渲染和 GPU 推理的总算力成本。
2. **【Analysis】** 二值奖励对稀有成功很脆弱；若一组样本全失败，dynamic sampling 只能继续花预算探索，不能提供中间方向。
3. **【Code】** 当前公开实现围绕 OpenVLA/OpenVLA-OFT 的离散 action-token 头，官方 checkpoint 因输入视角和 action head 差异不能直接复用；对 diffusion/flow-matching VLA 的扩展尚未实现。
4. **【Analysis】** `pushcut` 在 Move Can Pot / Place A2B 中达到的仍是物体位于目标附近这一结果，因此推动可以是合法替代策略。Figure 5 是行为实例，没有报告推的出现频率、能耗或平均完成时间，也未排除大规模预训练里出现过推动。它支持“超出当前任务示范的策略”，不足以证明从所有先验之外发明了技能，更不是奖励黑客的直接证据；真实接触代价需要另外测量。

## 8. 启发与研究思考

**【Analysis】** SimpleVLA-RL 给出的最有价值结论是：VLA 的 scaling 不一定等同于继续收集更多人类轨迹。一个可行的组合是“少量示教负责冷启动，仿真 RL 负责扩大行为分布，真实评测负责校准迁移”。

后续值得追问三件事：第一，能否用 curriculum 或轻量过程奖励降低“能力阈值”；第二，如何把 action chunk 的连续不确定性纳入 GRPO，而不是只对离散 token 做 ratio；第三，如何把安全约束、能耗和动作平滑加入 outcome reward，使 `pushcut` 一类新策略在真实机器人上同样可靠。
